# 个人分类与资金账户迁移

迁移为 `000012_personal_catalogs`。该版本保留了共享平台 / 商家目录，后续 `000015_personal_voucher_platforms` 已将它改为个人目录，见[平台 / 商家迁移说明](personal-platform-migration.md)。消费信用类型仍读取数据库目录。个人分类、资产与负债只向本人开放，包含只读角色的目录管理；资金与管理员设置权限另行校验。

## 上线前与对账

先停止账务写入及后台到期任务，备份完整数据库，并在独立恢复库验证本迁移。迁移会复制旧分类，不复制任何资金账户余额或券成本。对共享资产按完整资金链确定唯一使用人；存在多个历史使用人 / 既有负债所有者时整体归初始管理员。已有个人负债不改归属。原分类 ID 保留给初始管理员，其他账号有独立副本。新默认资产为零余额。

`catalog_account_ownership` 保存逐户归属原因与资金链标识，`catalog_before_*` / `catalog_after_*` 保存原始及迁移完成后的精确快照。这些表仅供数据库管理员对账，不提供给普通 HTTP 查询。快照包含财务历史和用户信息，必须采用与原库相同的访问限制与备份策略。

迁移后执行 `scripts/catalog-migration-report.sql` 导出归属及逐户余额差异：所有原账户的差异必须为零；新默认资产单列为零，不并入旧账户比较。检查分类父子归属、流水 / 券归类、未用券总成本、账单与抵扣记录不变。`recurring_rules.blocked_reason` 和 `installment_terms.blocked_reason` 列出旧跨账号配置：对应本人从个人目录选择合法账户，原资金链及已发生金额保持。

切换匹配的前后端版本、清理旧统计缓存，核对四档角色个人目录、当前版本的个人商家目录、只读资金权限及后台任务后恢复写入。不要将仅支持共享资产的旧应用与个人目录 schema 混用。

## 回滚

down 首先逐表精确比较迁移完成快照，检查后续账户创建请求；任何个人编辑、新财务历史或提醒变化都会拒绝自动回滚。满足前置条件时才恢复原分类引用、原资产归属并删除迁移创建的零余额实例。全部检查先于恢复操作，不能靠强制跳过 guard 删除新数据。

已有业务写入时，应保留新 schema 修复问题；若必须回退，使用经对账的备份及匹配版本，或编写专门数据回迁。不同人的分类与期初余额不能自动合并。备份恢复前还须保留升级后的新增财务数据，明确其重放方案。

## 独立测试报告示例

`TestPersonalCatalogMySQLMigration` 的样本中，账号 1 为管理员、2 为成员、3 为只读成员。新账本同名目录及资金账户的实际标识始终不同。

| 原账户 | 迁移归属 | 原因 | 原余额 | 迁移余额 |
|---|---|---|---:|---:|
| 单人资产（10） | 成员 2 | 唯一历史使用者 | 93.00 | 93.00 |
| 多人资产（11） | 管理员 1 | 多人使用整体保留 | 193.00 | 193.00 |
| 链路甲（12） | 成员 2 | 同一资金链唯一使用者 | 290.00 | 290.00 |
| 链路乙（13） | 成员 2 | 与链路甲一起归属 | 410.00 | 410.00 |
| 混合负债来源（14） | 管理员 1 | 两个既有负债归属锚点 | 490.00 | 490.00 |

样本中的既有个人負债归属保持，失配的周期模板暂停，未发生费用保留为阻塞；尝试回滚个人分类编辑被拒绝。创建并发测试对同账号、同请求标识的 16 个请求只创建一份账户；删除后重放旧标识不恢复该账户。
