# 个人目录排序迁移

`000016_catalog_ordering` 依赖 `000015_personal_voucher_platforms`。分类与账户继续使用已有 sort，不重写旧位置；平台 / 商家增加 sort，按 owner 分组、精确名称与 ID 的旧顺序回填，增加 `(owner_id, sort, id)` 索引。标识、名称、归属与创建时间均保留，迁移不修改财务表。

新增 `catalog_order_requests` 按 owner、目录作用域和 request_key 保存成功排序摘要，与批量位置更新在同一事务提交。客户端每次新拖动生成新标识，失败或响应丢失后复用原标识。记录用于拒绝已被后续不同排序取代的旧请求，包括目录后来改回原基准的情况；不授予其他目录管理或资金写权限。

上线前备份并暂停应用写入与 worker，执行迁移后配套发布后端与前端，验收后恢复写入。旧程序插入商家时使用默认 0，不能在回填后与新程序长期并行写入。服务重启不重复回填、不恢复用户删除的默认项。

down 删除新增商家排序列、索引及请求结果表，保留名称、个人归属、ID、历史文字和全部财务数据；分类与账户的原 sort 列保留。商家自定义顺序和排序请求重试记录会丢失，回退前在维护窗口导出 `voucher_platforms(id, owner_id, sort)`。旧程序恢复按名称显示商家；回退到 000015 之前还须满足该迁移自身的保护条件，不能借本次 down 合并私人目录。

开发验证使用本机 MySQL 的随机独立数据库，覆盖空库与既有目录 up / down、中文 / 大小写 / Unicode 回填、完整列表、并发创建 / 删除 / 排序、请求重放和中途存储失败回滚。浏览器测试使用内存财务账本与临时 Redis，不迁移真实开发库或生产库。
