# 理财产品接入与理财零钱

## 新增同银行产品

唯一维护的产品清单是 `backend/internal/wealthdata/products.json`。每一条代表一个准确的份额代码；登记编码相同的 A/E 等份额不能互相替代。清单保存银行、适配器、代码、名称、登记编码、币种、估值口径、成立日、官网页面、来源代码和订单策略，不保存个人持仓或收益。

1. 从官方来源核对完整身份、单位净值口径和历史数据，向清单追加记录。当前只接受 CNY 单位净值产品。`order_policy` 使用 `confirmed_facts`，只有已核实的周利宝使用 `zhoulibao_20250402`。`default_cash_policy` 可省略（通用次日确认估算）或指定已经核实的渠道策略；余利宝优享版为 `yulibao_20250715`。
2. 在 `backend` 执行 `go generate ./internal/wealthdata`，同步生成 `collector/products.json`。不要直接编辑生成的副本。后端测试会检查两份文件一致。
3. 运行 `go run ./cmd/wealth-catalog -code 新份额代码 -sql`，把输出放进下一编号的 up SQL，并配套有个人引用时拒绝破坏性回滚的 down SQL。工具只输出 SQL，不连库、不自动执行，也不自动开放产品；生成记录默认处于 `pending_validation`。
4. 按接入证据和现有准入流程开放目录，执行适配器、隔离 MySQL、既有产品和桌面/手机验收。迁移不得创建个人账户、份额或交易。

同银行、同接口协议的产品只需配置、公共目录迁移及身份核验，服务、持仓计算、支付选择器和定时任务无需添加产品代码分支。苏银采集器只从清单选出 `suyin` 适配器，仍限制为固定官网域名、产品详情路径和净值请求路径；民生原生 HTTP 适配器在每次采集前核验传入的完整产品身份，再完整翻页查询净值。

## 新增银行

实现 `wealthdata.Source` 的 `Configured()` 和 `Fetch(ctx, product, window)`，并在 `cmd/server/main.go` 的路由注册一次。适配器收到完整、已校验的产品元数据，应负责身份、分页、日期、精度、完整性和来源校验，返回统一的 `wealthdata.NAV`。不要把数据抓取、凭据或银行字段传进个人账户、持仓和收益计算模块。

来源失败应返回共用错误，保留已有有效净值；只有整批验证成功后才能提交。支持新交易规则时，另行增加经过核实的规则策略，不能从银行或产品名字猜交易时点。新增采集器配置/镜像不代表正在运行的固定版本三天采样已切换或已通过。

## 余利宝等理财零钱的使用

新建时，在“账户管理 → 新建账户”选择资产类别“理财零钱”，填写起始余额、选择“民生理财贵竹固收增利天天盈9号理财产品E”等已接入产品并选择起算基准日，一次保存即可创建。无需先创建普通账户再关联，记账窗口内的新建账户也支持相同操作。基准日默认今天，可以改为已核对的历史日期；起始余额为非负金额，按该日结束时已确认资金起算，从下一日起随已披露净值记收益。

已有普通账户继续使用兼容入口：找到现有“余利宝”，点击“理财零钱”，启用并选择产品及已核对基准日，保留账户编号、期初和原流水。新建和历史关联共用产品身份、日期及规则校验，不另建一份银行理财持仓。

创建 API 仍为 `POST /api/v1/accounts`：`type=asset`、`asset_class=wealth_cash`、`opening_balance`、`request_key`，以及 `wealth_cash: { product_id, start_date }`。账户、关联、审计和创建回执在同一财务事务提交。缺少/非法配置及保存失败全部回滚；相同内容和标识重试返回原账户，复用标识改动余额、产品或日期会冲突。新字段可选且普通账户摘要兼容旧版本。本次直接新建功能使用已有 000021 表结构，无需新增迁移。

普通收入、支出、转账、购券、还款等现金入口均可选择 `wealth_cash`。记账后账户余额立即响应，理财零钱页根据同一账户流水估算已确认、待确认和未再申购现金。转入确认日、申请时间可在普通流水修改；跨两个理财零钱账户的转账仍只有一笔现金转账，两侧各保留时点信息。

复用原有上海时间 08/12/18/22 净值同步槽及每 30 秒补偿任务。只有钱包关联而没有独立理财持仓时，产品也会被追踪。新增净值后，服务把相应净值区间收益写入普通流水：正收益为收入、负收益为投资损益支出、零额仅保留收益明细。各账户/净值日只存在一条有效收益，收益、流水、审计和计算版本原子提交；正常资金流水修改后由下次补偿重算自动部分。

自动收益影响账户余额、总资产和资产曲线，并显示在流水中；不计入生活收入、消费或预算。用户可从流水点击“修改收益”，也可从理财零钱详情改成实际收益或“校准余额”。校准的差额计入最后一笔收益，后续同步保留采用值并更新参考估算。遗漏的收支应先补记，避免把漏记本金作为收益。收益已封账时拒绝修改；历史净值变化涉及封账时保留原流水并标“封账待核对”，重开后才能重算。

手动区间收益记录原始起始日期。之后若补发区间内的历史净值，新拆分日期显示“已含在手动区间收益中”，不在手动金额之外再计一次收益。累计净值与单位净值差额变化时提示分红待核对，保留采用值，不把除息直接当作亏损。账户停用自动收益后回到普通现金类型，已入账收益、历史和审计均保留。

## 估算边界和规则来源

[网商银行优享版规则](https://render.mybank.cn/p/yuyan/180020590000000085/index.html?chInfo=tabs)明确资金确认后才享有收益，转出按丙→乙→甲、同类后进先出。快转自有效申请日（含当日）不再享有对应收益，依据其引用的[快速转出服务协议](https://render.mybank.cn/p/yuyan/180020590000000080/index.html)。支付支出默认快转；普通转出须填写实际最后收益日。支付失败退款进入现金，不自动再申购。规则摘录和版本见 `docs/research/yulibao-premium-20250715.md`。

机构并未承诺所有转入都在 T+1 确认。缺少实际确认日时，系统依据已披露净值日期和 15:00 截点估算下一交易日，未来交易日尚不可知时保持待确认；这是可修正估算，不是银行真实订单或真实份额。通用策略则按次日估算。跨没有单日披露的净值区间，内部用线性净值路径估算每日资金权益，最终只在实际披露日汇总入账，不伪造公开净值或提前生成自然日收益。

账户余额是项目的记账余额，无法读取银行实际可用额度、交易确认、节假日安排或快转限额；实际记录和校准优先。初次余额包含尚未确认的资金时，应选更准确的基准日或待资金确认后启用。

## 升级、回滚和验收

升级前备份财务库，先完成 000018–000020，再升级 000021 并配套发布前后端。000021 不自动关联任何真实账户。有配置、时点、收益或审计历史时 down 会在删除前拒绝，保留数据采用前向修复；不能靠删除财务数据实现版本回退。

本机先运行 MySQL 与 Redis。在私有环境设置 `WEALTH_MYSQL_DSN` 后，在 backend 执行 `go test ./internal/service -run '^TestWealthCashMySQL' -count=1 -v`。测试只使用随机临时数据库并清理。完整验证为 `go test ./...`、`go vet ./...`、`go build ./cmd/server`，以及 frontend 的 `npm run typecheck`、`npm run test:unit`、`npm run build`。

浏览器验收沿用 README 的隔离 `wealth-browser` fixture，并设置 `CMBCWM_BROWSER_FIXTURE=1`。前端运行 `node e2e/wealth-cash.mjs`（`WEALTH_E2E_BASE` 指向本机预览），手机加 `WEALTH_E2E_MOBILE=1`。脚本拒绝连接非本机或非测试账本，覆盖原地关联、默认快转、流水收益修改、净值修订保护、校准及停用留史。采集器在 collector 执行 `npm test`，设置 `WEALTH_BROWSER_EXE` 可运行真实本机 Chrome 的路由拦截验收，不依赖银行网络。
