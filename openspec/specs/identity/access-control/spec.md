# identity/access-control Specification

## Purpose

定义四档角色对系统各类资源的操作矩阵，作为 API 鉴权与界面入口显隐的统一依据。

## Requirements

### Requirement: 设置类操作仅限管理员

账期结算日配置、封账与解封、预算配置、用户与角色管理 SHALL 仅管理员可操作；其他角色执行时 MUST 返回 403。分类、平台 / 商家目录与资产 / 负债账户管理 SHALL 按各自能力的本人归属规则开放给全部有效登录账号，包含只读成员；此能力 MUST NOT 授予流水、购券、还款、分期或其他资金写权限。管理员 MUST NOT 因角色绕过其他账号的分类、平台 / 商家或资金账户归属。周期记账模板管理按 `recurring-entries` 能力执行，并同时受所引用个人资源归属限制。

#### Scenario: 记账员修改账期设置
- **WHEN** 记账员调用修改结算日的接口
- **THEN** 返回 403，设置不发生变化

#### Scenario: 普通成员修改分类
- **WHEN** 普通成员新增、重命名或按删除约束删除本人的分类
- **THEN** 操作成功，无需管理员处理，其他账号目录不变化

#### Scenario: 只读成员设置自己的负债账户
- **WHEN** 只读成员修改本人负债账户的名称、账单日期或启停状态
- **THEN** 按既有账户规则允许保存，但不提供还款或创建分期等资金操作入口

#### Scenario: 管理员管理其他人的负债账户
- **WHEN** 管理员尝试访问或修改另一个账号的个人负债账户
- **THEN** 返回 403，管理员的前端入口也不将该账户列为可管理资源

#### Scenario: 只读成员管理资产账户
- **WHEN** 只读成员创建或修改自己的资产账户，随后尝试写入流水
- **THEN** 账户按合法期初余额和历史约束保存，流水写入仍返回 403

#### Scenario: 全角色管理本人商家
- **WHEN** 任一有效登录角色新增、重命名或按引用约束删除本人平台 / 商家
- **THEN** 操作成功，其他账号目录和所有账务数据不变化

#### Scenario: 管理员管理他人商家
- **WHEN** 管理员使用另一个账号的商家选项 ID 调用重命名或删除
- **THEN** 返回 403，管理员身份不扩大目录管理范围

### Requirement: 流水写权限矩阵
管理员与记账员 SHALL 可创建、修改、删除本人资源范围内的流水；普通成员 SHALL 可创建流水且仅能修改与删除创建人为自己的流水；只读成员 MUST 不能创建、修改或删除任何流水。所有角色 SHALL 同时校验受影响账户与分类归属，MUST NOT 因创建人权限、管理员身份或记账员身份绕过他人的个人资源限制；遗留跨账号财务关联按 `transactions` 的历史兼容规则执行。

#### Scenario: 普通成员修改自己的流水
- **WHEN** 普通成员修改创建人为自己且账户与分类均为本人资源的流水
- **THEN** 修改成功

#### Scenario: 普通成员修改他人流水
- **WHEN** 普通成员尝试修改创建人为其他用户的流水
- **THEN** 返回 403，流水保持不变

#### Scenario: 只读成员尝试记账
- **WHEN** 只读成员提交记账请求
- **THEN** 返回 403，且界面不展示记账入口

#### Scenario: 管理员使用他人资产账户
- **WHEN** 管理员直接提交另一账号资产账户 ID 进行支出、转账或退款
- **THEN** 返回 403，不改变任何账户或流水

### Requirement: 查看权限对全员开放

四档角色 SHALL 均可查看本人资源归属范围内的账户、分类、流水、券、提醒及统计；管理员 MUST NOT 因角色扩大个人资源查看范围。预算 SHALL 按 `budgets` 保留账本总预算配置并展示本人的分类及消费进度。只读角色在相同归属范围内 SHALL 获得与其他角色一致的查看能力。平台 / 商家选项目录 SHALL 按 `voucher-platform-options` 对全部已登录角色开放本人读取和维护能力，MUST NOT 返回或同步其他账号的个人目录；目录管理 MUST 不授予券、流水或其他受限资源的写入权限。

#### Scenario: 只读成员查看统计
- **WHEN** 只读成员打开统计页
- **THEN** 看到相同本人资源范围内与其他角色一致的数据，不含他人的个人账户资金

#### Scenario: 只读成员创建非账务选项
- **WHEN** 只读成员创建平台 / 商家选项后尝试登记购券或记账
- **THEN** 本人选项创建成功且其他账号目录不变化，购券与记账请求仍返回 403，账户余额、消费和预算不变化

#### Scenario: 个人负债查看隔离
- **WHEN** 任一角色查询账户、负债或分类列表
- **THEN** 仅包含本人所属的账户和分类，不出现其他账号的资产账户、负债账户或分类树

#### Scenario: 商家目录查看隔离
- **WHEN** 任一角色请求平台 / 商家目录或通过查询参数指定另一账号 owner_id
- **THEN** 只能获得本人目录，参数不扩大读取范围

### Requirement: API 与界面双重执行

权限 MUST 同时体现在服务端 API 拒绝（403）与前端入口隐藏或禁用两处，界面隐藏 MUST NOT 作为唯一防线。首页、流水页及各业务表单 SHALL 使用一致的角色与资源归属语义，只读成员 MUST 不出现普通记账、购券、还款或分期提交入口；本人分类、平台 / 商家和账户管理 SHALL 按各自能力保留。“我的”及个人账户 / 分类 / 平台商家路由 SHALL 对全部有效登录角色开放，管理员专属设置路由仍须保持原门禁。平台 / 商家列表和操作入口 MUST 只包含本人条目，直接调用他人条目的维护接口仍 MUST 由服务端拒绝。

#### Scenario: 直接调用高权限 API
- **WHEN** 只读成员绕过界面直接调用记账接口
- **THEN** 服务端返回 403，数据不发生变化

#### Scenario: 只读成员浏览记账入口
- **WHEN** 只读成员查看首页和流水页
- **THEN** 可查看本人数据与导出，不显示快捷记账、记一笔或购券提交入口，仍可从“我的”管理本人分类、商家和账户

#### Scenario: 成员查看他人普通流水
- **WHEN** 普通成员查看历史迁移后属于本人资源但创建人为其他用户的普通流水
- **THEN** 不显示编辑与删除入口，管理员和记账员也必须满足全部受影响个人资源的归属约束

#### Scenario: 非管理员直接访问管理路由
- **WHEN** 已登录普通成员直接访问 /accounts、/categories 或 /platforms，再访问 /settings
- **THEN** 前三者可管理本人资源，账期设置仍按管理员门禁拒绝

#### Scenario: 绕过界面维护他人商家
- **WHEN** 普通成员或只读成员直接请求重命名他人平台 / 商家条目
- **THEN** 服务端返回 403，前端列表不提供该条目的操作入口

### Requirement: 个人基金配置与资金权限分离
全部有效登录角色 SHALL 可查看及配置本人基金账户，按 `fund-accounts` 的历史与封账约束录入或更正合法期初持仓，并可刷新本人基金行情。基金买入、赎回、现金分红、再投资及对应资金事件的修正或撤销 MUST 遵循现有记账资格和创建人权限，只读成员 MUST 不具有这些资金写权限。基金账户、持仓、操作事件及关联现金账户 MUST 同时属于登录账号；管理员与记账员 MUST 不因角色绕过其他账号归属。账号范围 MUST 从认证身份确定，MUST NOT 信任请求中指定的 owner_id。界面与 API SHALL 使用相同权限，所有基金账户与个人汇总均按本人隔离，公共行情缓存不授予他人持仓访问权。

#### Scenario: 只读成员配置期初持仓
- **WHEN** 只读成员创建本人基金账户并录入合法期初持仓，随后尝试登记买入
- **THEN** 账户与期初按规则保存，买入入口不可提交且直接资金 API 返回 403，不能额外扣现金或增加交易份额

#### Scenario: 管理员读取他人基金
- **WHEN** 管理员通过持仓 ID、基金账户 ID 或资金账户 ID 访问另一账号的基金数据或登记操作
- **THEN** 返回 403，个人列表、总数、历史、估值和资金都不会泄露或变化

#### Scenario: 普通成员撤销本人事件
- **WHEN** 普通成员对本人创建、本人资源范围内且满足末笔与封账约束的基金事件执行撤销
- **THEN** 操作成功，不能因此撤销创建人为其他账号或涉及他人资源的历史事件

#### Scenario: 后台同步使用持久化归属
- **WHEN** 无用户在线或甲触发公开行情刷新后后台更新同代码持仓
- **THEN** 各持仓按自身保存的 owner_id 重估，不借甲的身份写入乙资金，也不向甲返回乙的同步详情

### Requirement: 个人黄金配置与资金权限分离
全部有效登录角色 SHALL 可查看、创建和配置本人黄金账户，按 `gold-accounts` 规则录入或合法更正期初，并手动刷新本人可访问产品的公开报价。黄金买入、卖出及其修正或撤销 MUST 沿用流水写入资格和创建人权限，只读成员 MUST 无资金写权限。账户、事件、持仓、现金账户及审计读取 MUST 同时校验本人归属，管理员及记账员不得跨账号，owner_id MUST 从认证身份确定。公共报价共享与后台更新 MUST 不授予另一账号的个人数据访问权，界面和 API SHALL 双重执行。

#### Scenario: 只读成员建立期初但不能买卖
- **WHEN** 只读成员创建本人黄金账户并录入合法期初，随后直接调用买入或卖出接口
- **THEN** 账户和期初可保存，买卖接口返回 403 且前端不提供提交入口，现金和交易不变

#### Scenario: 管理员不能查询他人持仓
- **WHEN** 管理员使用其他账号黄金账户 ID 查询持仓、事件、估值、审计或提交买卖
- **THEN** 返回 403，公共价格可共享但他人账户及资金数据不返回

#### Scenario: 后台独立使用持久化归属
- **WHEN** 无用户在线或甲触发手动刷新后新报价需更新所有黄金持仓
- **THEN** 各持仓按自身归属更新估值，甲响应只含其有权读取的数据，不借甲身份操作乙的资金
