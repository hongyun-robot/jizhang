# identity/access-control Specification

## Purpose

定义四档角色对系统各类资源的操作矩阵，作为 API 鉴权与界面入口显隐的统一依据。

## Requirements

### Requirement: 设置类操作仅限管理员
账期结算日配置、封账与解封、预算配置、用户与角色管理 SHALL 仅管理员可操作；其他角色执行时 MUST 返回 403。分类与资产 / 负债账户管理 SHALL 按各自能力的本人归属规则开放给全部有效登录账号，包含只读成员；此能力 MUST NOT 授予流水、购券、还款、分期或其他资金写权限。管理员 MUST NOT 因角色绕过其他账号的分类或资金账户归属。周期记账模板管理按 `recurring-entries` 能力执行，并同时受所引用个人资源归属限制。

#### Scenario: 记账员修改账期设置
- **WHEN** 记账员调用修改结算日的接口
- **THEN** 返回 403，设置不发生变化

#### Scenario: 普通成员修改分类
- **WHEN** 普通成员新增、重命名或按删除约束删除本人的分类
- **THEN** 操作成功，无需管理员处理，其他账号目录不变化

#### Scenario: 只读成员设置自己的负债账户
- **WHEN** 只读成员修改本人负债账户的名称、账单日期或启停状态
- **THEN** 按既有账户规则允许保存，但不提供还款或创建分期等资金操作入口

#### Scenario: 管理员管理其他人的负债账户
- **WHEN** 管理员尝试访问或修改另一个账号的个人负债账户
- **THEN** 返回 403，管理员的前端入口也不将该账户列为可管理资源

#### Scenario: 只读成员管理资产账户
- **WHEN** 只读成员创建或修改自己的资产账户，随后尝试写入流水
- **THEN** 账户按合法期初余额和历史约束保存，流水写入仍返回 403

### Requirement: 流水写权限矩阵
管理员与记账员 SHALL 可创建、修改、删除本人资源范围内的流水；普通成员 SHALL 可创建流水且仅能修改与删除创建人为自己的流水；只读成员 MUST 不能创建、修改或删除任何流水。所有角色 SHALL 同时校验受影响账户与分类归属，MUST NOT 因创建人权限、管理员身份或记账员身份绕过他人的个人资源限制；遗留跨账号财务关联按 `transactions` 的历史兼容规则执行。

#### Scenario: 普通成员修改自己的流水
- **WHEN** 普通成员修改创建人为自己且账户与分类均为本人资源的流水
- **THEN** 修改成功

#### Scenario: 普通成员修改他人流水
- **WHEN** 普通成员尝试修改创建人为其他用户的流水
- **THEN** 返回 403，流水保持不变

#### Scenario: 只读成员尝试记账
- **WHEN** 只读成员提交记账请求
- **THEN** 返回 403，且界面不展示记账入口

#### Scenario: 管理员使用他人资产账户
- **WHEN** 管理员直接提交另一账号资产账户 ID 进行支出、转账或退款
- **THEN** 返回 403，不改变任何账户或流水

### Requirement: 查看权限对全员开放
四档角色 SHALL 均可查看本人资源归属范围内的账户、分类、流水、券、提醒及统计；管理员 MUST NOT 因角色扩大个人资源查看范围。预算 SHALL 按 `budgets` 保留账本总预算配置并展示本人的分类及消费进度。只读角色在相同归属范围内 SHALL 获得与其他角色一致的查看能力。平台 / 商家选项目录的读取与创建 SHALL 继续按 `voucher-platform-options` 对全部已登录角色开放并由全员共享；目录创建 MUST 不授予券、流水或其他受限资源的写入权限。

#### Scenario: 只读成员查看统计
- **WHEN** 只读成员打开统计页
- **THEN** 看到相同本人资源范围内与其他角色一致的数据，不含他人的个人账户资金

#### Scenario: 只读成员创建非账务选项
- **WHEN** 只读成员创建平台 / 商家选项后尝试登记购券或记账
- **THEN** 选项创建成功且其他账号可复用，购券与记账请求仍返回 403，账户余额、消费和预算不变化

#### Scenario: 个人负债查看隔离
- **WHEN** 任一角色查询账户、负债或分类列表
- **THEN** 仅包含本人所属的账户和分类，不出现其他账号的资产账户、负债账户或分类树

### Requirement: API 与界面双重执行
权限 MUST 同时体现在服务端 API 拒绝（403）与前端入口隐藏或禁用两处，界面隐藏 MUST NOT 作为唯一防线。首页、流水页及各业务表单 SHALL 使用一致的角色与资源归属语义，只读成员 MUST 不出现普通记账、购券、还款或分期提交入口；本人分类和账户管理与共享平台 / 商家目录创建 SHALL 按各自能力保留。“我的”及个人账户 / 分类路由 SHALL 对全部有效登录角色开放，管理员专属设置路由仍须保持原门禁。

#### Scenario: 直接调用高权限 API
- **WHEN** 只读成员绕过界面直接调用记账接口
- **THEN** 服务端返回 403，数据不发生变化

#### Scenario: 只读成员浏览记账入口
- **WHEN** 只读成员查看首页和流水页
- **THEN** 可查看本人数据与导出，不显示快捷记账、记一笔或购券提交入口，仍可从“我的”管理本人分类和账户

#### Scenario: 成员查看他人普通流水
- **WHEN** 普通成员查看历史迁移后属于本人资源但创建人为其他用户的普通流水
- **THEN** 不显示编辑与删除入口，管理员和记账员也必须满足全部受影响个人资源的归属约束

#### Scenario: 非管理员直接访问管理路由
- **WHEN** 已登录普通成员直接访问 /accounts 或 /categories，再访问 /settings
- **THEN** 前两者可管理本人资源，账期设置仍按管理员门禁拒绝
