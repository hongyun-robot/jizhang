## Why

现有账户只支持由资金流水推导余额，无法表达基金持仓随净值涨跌的市值，基金资产也无法准确进入个人总资产和历史资产曲线。扶摇接口已用现有 `FUYAO_API_KEY` 验证能够查询 `023564.OF` 的资料与净值，需要将公开行情与各账号独立的持仓、成本和交易记录结合，持续计算投资盈亏。

## What Changes

- 增加本人所属的基金资产账户，一个账户可管理多只场外净值型基金；支持股票、混合、债券、ETF 联接等按单位净值估值的场外持仓，首版不支持货币基金、场内 ETF 市场价格或外币持仓。扶摇的细分类别与币种契约不充分，登记者须明确确认“人民币场外净值型”口径，系统不按简称或净值数值猜类型。
- 支持按基金代码录入期初确认份额、成本价和持仓生效日期。个人历史从建账起点开始，缺少历史份额时不反算历史日盈亏；`023564 / 5028.62 / 1.4119` 仅用于测试，用户自行添加实际持仓。
- 记录已完成的买入、赎回、现金分红和红利再投资，关联本人的现金资产账户及实际生效、资金发生日期；采用加权平均成本，买入费用计成本、部分赎回按比例结转成本、现金分红不冲减剩余成本。
- 基金净值变动、分红、已实现收益和投资费用单独统计，不进入日常收入、支出、结余或预算。本金资金往来以受基金事件管理的转账呈现，避免赎回时重复确认已展示的盈亏。
- Go 后端使用服务器配置的 `FUYAO_API_KEY` 直接调用扶摇 REST API；工作日 19:00–23:00 每半小时检查，各代码获得新报价并完成估值后停止当晚检查，次日 04:00 独立补查一次前一工作日。启动恢复仅在相应时段进行，冷取价和手动刷新保留。延迟、接口故障和限流保留上次有效净值并显示数据日期及状态。
- 基金账户的持仓市值及必要的待结算资金进入本人账户余额、首页总资产及每日资产曲线；基金账户不作为普通消费、还款、购券或周期模板支付账户。
- 所有有效登录角色均可配置本人基金账户和合法期初持仓；交易记录继续遵守现有记账权限，只读成员不能写资金交易，管理员不能跨账号。基金交易保护、封账、撤销、缓存隔离及并发去重与现有财务约束衔接。

## Capabilities

### New Capabilities

- `fund-accounts`: 个人多基金持仓、扶摇行情同步、加权成本、已完成交易与分红、日盈亏和投资专属界面。

### Modified Capabilities

- `accounts`: 明确现金与基金资产子类，扩展余额来源、总资产、删除约束及支付账户可用性。
- `identity/access-control`: 将个人基金查看、账户配置、期初录入与资金操作权限分别纳入现有账号隔离规则。
- `statistics`: 将基金市值纳入逐日资产曲线，明确投资收益与费用不进入普通收支、预算相关统计。
- `transactions`: 增加基金事件管理的资金转账标识、关联、展示、导出及普通编辑删除保护。
- `billing-periods`: 约束基金财务事件的跨日期封账检查，区分公开净值同步与账务修改。

## Impact

- 后端：新增基金模块、报价适配器和配套迁移；接入账户聚合、统计历史、权限、资金事务、路由与 `backend/cmd/server/main.go` 中现有 cron 生命周期。普通资产和负债的既有资金口径保持兼容。
- 前端：在账户管理及“我的”增加基金入口与多持仓详情，提供期初录入、交易、分红、历史、状态和刷新；扩展账户选择器、流水关联展示及会话范围缓存。
- 配置：`backend/internal/config/config.go`、`.env.example`、`docker-compose.yml` 和本地启动说明读取及注入 `FUYAO_API_KEY`，密钥仅留在服务端。Go 使用标准 HTTP 客户端，无需安装 MCP、CLI 或 Python SDK。
- 验证：金额与成本、实际资金日期、分红除息、全量赎回、历史起点、账号隔离、封账、并发重试、源数据异常、停用账户及迁移回滚测试；新增隔离账本的桌面与移动端 Playwright 验收。
- 本变更在独立 worktree 实施并验收；不会预置真实持仓、调用外部交易下单、自动处理个人分红选择或执行生产部署。
