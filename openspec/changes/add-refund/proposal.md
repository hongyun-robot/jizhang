# Proposal

## Why

账本没有退款的表达方式：券到期退款、网购退货等真实资金回流只能被记成一笔"收入"，导致收入虚增、原支出不冲减、预算不回吐——收支报表说谎。用户需要一个语义正确的退款机制。

## What Changes

- 流水新增第 4 种类型 `refund`（退款）：金额恒正，使账户余额增加，统计与预算中按"负支出"处理，MUST NOT 计入收入。
- 退款流水 MAY 通过新增可空字段 `related_txn_id` 关联一笔原支出；关联时自动继承原支出的分类与账户（可改），原支出展示"已退 ¥x"并可跳转。
- 允许一笔支出对应多笔部分退款，退款总额超过原支出仅前端提示、不硬拦截。
- 退款按到账日归属账期（`entry_date`/`period_key`），不回填原支出所在月（原月可能已封账）。
- 删除约束：存在关联退款的支出流水不可删除，须先处理退款。
- 退款入口有两个：流水列表支出行的"退款"操作（预填表单）与记账表单的"退款"类型选项；均按现有流水写权限矩阵控制。
- 统计口径：分类占比饼图只绘制净额 > 0 的分类，净额 ≤ 0 的分类在图例/列表如实显示负值；预算消耗在退款到账月回吐，净消耗为负时展示"本月已退回 ¥x"。
- 不建券/预付卡实体，不做导入与平台自动识别（系统无导入管线）；退款全部手动录入。

## Capabilities

### New Capabilities

- `refunds`: 退款流水的类型语义、与原支出的可选关联、部分/多次退款规则、账期归属、分类继承、删除约束与权限封账约束。

### Modified Capabilities

- `transactions`: 「记账三态」扩展为含退款的第四类流水；退款流水参与筛选、搜索、分页与 CSV 导出（带退款标记）。
- `accounts`: 「流水关联账户」与「余额与总资产计算」明确退款流水单账户、余额增加的贡献方式。
- `budgets`: 「预算消耗计算」由"支出流水合计"改为"支出 − 关联退款口径"，退款计入到账月回吐；「进度与超支展示」新增净消耗为负时的"本月已退回"展示。
- `statistics`: 「分类占比」与「收支趋势」明确退款按负支出计入、负净额分类的展示规则。

## Impact

- 后端：`transactions` 表迁移（`kind` ENUM 增 `refund`、新增可空 `related_txn_id`）；`model.TxnKind`、`transaction_service` 校验与关联/删除规则、`txn_handler` 请求 DTO；`account_repo`/`stats_repo`/`budget_repo` 的 CASE 分支；CSV 导出标记；写钩子（缓存失效、预算重估）沿用现有链路。
- 前端：`types.ts` 类型、`TxnFormModal` 第 4 类型选项、`Records.tsx` 行内"退款"动作与关联/已退标记、预算进度"本月已退回"文案、统计页分类占比负值图例。
- 测试：新增 `frontend/e2e/refunds.mjs` 浏览器走查脚本（沿用现有 playwright-core e2e 体系），覆盖 UI + 后端整套逻辑与恢复基线。
- 权限与封账：沿用现有流水写权限矩阵（`permission.go`）与 `guardOpen` 封账锁，无需新增规则，仅扩展覆盖场景。
- 兼容性：存量流水不受影响；`related_txn_id` 可空、`refund` 为新增枚举值，迁移无破坏性。
