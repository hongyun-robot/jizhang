# Spec Delta

## ADDED Requirements

### Requirement: 筛选状态跨路由保留
流水页的筛选条件（区间、类型、账户、分类、关键字、金额区间）与页码 MUST 序列化到 URL；底部 Tab 切换、浏览器前进后退与外部分享链接 MUST 能恢复到同一视图状态；首页跳转定位（locateId）流程 MUST 保持既有行为不回归。

#### Scenario: 切 Tab 后返回
- **WHEN** 用户在流水页筛选"本月 + 支出 + 微信账户"后切到统计页再切回流水
- **THEN** 筛选条件与页码完整保留，列表按原条件展示

#### Scenario: 浏览器后退
- **WHEN** 用户修改筛选条件后点击浏览器后退
- **THEN** 恢复上一组筛选条件与页码，列表随之刷新

#### Scenario: 分享链接
- **WHEN** 用户复制流水页 URL 发给他人并打开
- **THEN** 对方看到与分享者一致的筛选条件与页码

#### Scenario: 定位跳转不回归
- **WHEN** 用户从首页点击最近流水跳转到流水页定位该笔
- **THEN** 目标行仍被定位高亮，定位后的一次性状态清空不破坏 URL 中的筛选条件

### Requirement: 移动端列表加载方式
移动形态下流水列表 MUST 支持上拉加载下一页（追加展示）与下拉刷新；通过分页控件翻页后 MUST 回到列表顶部；分页控件 MUST 保留作为加载方式的兜底。

#### Scenario: 上拉加载
- **WHEN** 用户滚动到列表底部
- **THEN** 自动请求并追加下一页，页码与总数同步更新，加载中显示进行中指示且不重复触发

#### Scenario: 分页控件翻页回顶
- **WHEN** 用户点击分页控件切到第 3 页
- **THEN** 列表加载后回到顶部，用户从第一条开始浏览

#### Scenario: 下拉刷新
- **WHEN** 用户在列表顶部下拉
- **THEN** 按当前筛选条件重新请求并展示最新数据，失败时呈现错误态与重试入口

### Requirement: 筛选栏移动端收纳
移动形态下流水页首屏 MUST 优先展示列表；筛选控件 MUST 收纳为带条件摘要的入口，展开后可编辑全部条件；已生效的条件 MUST 常驻可见。

#### Scenario: 手机打开流水页
- **WHEN** 在手机视口打开流水页
- **THEN** 首屏可见列表内容，筛选收纳为单行入口并显示已生效条件摘要，筛选栏不再占据多行把列表推出首屏

#### Scenario: 展开编辑条件
- **WHEN** 用户点开筛选入口
- **THEN** 可编辑区间、类型、账户、分类、关键字与金额区间，收起后摘要与列表同步更新

#### Scenario: 清除筛选
- **WHEN** 用户存在生效条件时点击清除
- **THEN** 条件重置为默认区间，摘要与列表同步刷新
