# Spec Delta

## ADDED Requirements

### Requirement: 删除二次确认防重
删除流水的二次确认 MUST 在提交期间显示进行中状态并禁用重复确认；请求失败时列表 MUST 保持原状并给出错误提示。

#### Scenario: 连点确认删除
- **WHEN** 用户快速连点删除确认按钮
- **THEN** 仅发起一次删除请求，确认按钮呈现进行中状态且不可再次触发

#### Scenario: 删除失败
- **WHEN** 删除请求因网络或权限失败
- **THEN** 流水仍在列表中，展示错误消息，余额与统计不变

### Requirement: 流水行操作在移动视口可达
移动形态下每条流水的操作入口（编辑、退款、删除、账单、查看券等）MUST 完整可见、命中区达标，MUST NOT 依赖悬停显现，且 MUST NOT 因空间不足被裁切或重叠。

#### Scenario: 手机查看流水行操作
- **WHEN** 在手机视口打开流水页
- **THEN** 每行操作按钮完整显示在行内，可单次点中，文字与红色删除态清晰可辨

#### Scenario: 操作较多的行
- **WHEN** 某行同时存在"账单 / 编辑 / 退款 / 删除"多个操作
- **THEN** 操作在窄屏下换行或收纳展示，全部可达且不互相遮挡

#### Scenario: 无权限用户
- **WHEN** 只读角色查看流水行
- **THEN** 不出现编辑/删除入口，与既有权限矩阵一致
