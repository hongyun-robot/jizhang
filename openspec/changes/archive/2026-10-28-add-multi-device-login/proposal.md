## Why

当前登录已能生成多个 refresh token，但失效或已轮换 token 的刷新请求会撤销整个账号，多个浏览器标签页之间也没有刷新协调，容易互相踢下线。需要明确按设备类型并行登录的规则，让手机、平板、电脑稳定共存，并让同类替换和全设备退出立即生效。

## What Changes

- 自动将登录归为手机、平板、电脑三类，每个账号每类最多一个有效会话；三类可同时在线。同类新登录成功后替换旧会话，登录失败不影响原会话。
- 同一浏览器 Cookie 存储空间内的标签页共享登录会话，协调刷新、登录切换和退出，防止旧响应恢复已结束的会话。
- 为登录建立稳定会话标识；被替换、撤销或到期的会话，其 access token 与 refresh token 均不能继续使用。自然过期、刷新凭据失效和同类替换只影响对应会话。
- **BREAKING**：用户主动退出改为撤销该账号全部设备会话，入口明确显示“退出所有设备”。被动认证失败只清理客户端会话，不触发全设备退出。管理员重置密码、停用、调整角色继续撤销全设备。
- 服务端撤销立即生效；同浏览器标签页同步清理，其他设备在下一次请求或回到前台时显示失效。本次不增加跨设备实时推送。
- 保留 access 30 分钟、refresh 每次成功刷新后再延长 30 天的默认配置。设备类型依据浏览器信息自动判断，无法识别归电脑，接受误判及信息可伪造的限制。
- **BREAKING**：上线后旧登录统一失效，需要重新登录一次；不提供缺少会话标识的旧令牌兼容窗口。
- 本次不提供设备列表、指定设备远程下线、单设备退出入口、硬件指纹或设备绑定。

## Capabilities

### New Capabilities

无，沿用现有身份认证能力。

### Modified Capabilities

- `identity/user-auth`：增加设备分组与每类单会话、同类替换、即时撤销、多标签页协调及旧会话切换要求；修改刷新隔离与登出的作用范围，保留认证重试和会话数据隔离约束。

## Impact

- 后端：`internal/service/auth_service.go` 的令牌、Redis 状态与原子会话操作，`auth_handler.go` 的登录/刷新/退出，认证中间件、响应错误码，以及 `user_service.go` 的账号级撤销调用与测试。
- 前端：`auth/coordinator.ts`、`auth/session.ts`、认证 store、API 拦截器、路由守卫、登录页与“我的”退出入口；增加设备分类、跨标签页协调和回到前台校验。
- API：沿用 login/refresh/logout/me 路径；登录要求新版协议标记并可附加受限的浏览器能力信息，令牌结果增加会话元信息，401 区分可刷新过期与终止会话。logout 的全设备语义及凭据验证需要同步更新客户端。
- 浏览器兼容：通过 Web Locks 或 SharedWorker 代理串行认证写入；两者均不可用时明确暂停认证写入并提供恢复提示，避免迟到 Cookie 响应破坏新登录。
- Redis：采用新版会话键空间及会话级检查，登录替换、刷新和账号级撤销需原子化；不修改 MySQL 财务结构，不新增财务迁移。
- 验证：补齐多类型共存、同类并发替换、跨标签页刷新、全设备退出及撤销竞态；调整 `frontend/e2e/support/fixture.mjs` 及相关脚本，避免测试辅助登录与电脑浏览器互相替换。实施时运行 Go、前端单元/构建检查及隔离浏览器验收。
