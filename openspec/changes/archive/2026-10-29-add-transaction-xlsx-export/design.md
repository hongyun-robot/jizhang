## Context

动机和用户确认范围见 [proposal.md](proposal.md)，验收合同见 [transactions 增量规范](specs/transactions/spec.md)。本设计覆盖前后端导出链路，并引入 XLSX 写入依赖，因此保留独立设计文档。

已观察的现状：

- `frontend/src/pages/Records.tsx` 的 `doExport` 调用 `api/transactions.ts` 的 `exportTxns`，使用 `useRecordsState` 给出的完整筛选参数；现下载请求为 Blob，超时 30 秒。
- `backend/internal/handler/txn_handler.go` 的既有 `GET /api/v1/transactions/export` 只输出 CSV。`service/txn_export.go` 固定 13 列；`TransactionService.ExportRows` 使用 `personalFilter`、`ListAll`、`fillEffects`、`redactHistory`。
- `repository/transaction_repo.go` 的 `applyFilter` 和 `transactionOrderQuery` 已统一筛选和本人展示顺序；`ListAll` 当前无上限。无需重新定义查询语义。
- `fillEffects` 内包含券、基金、理财和负债关联补全，但相关查询有返回空值而不传递错误的路径，不能据此保证 XLSX 追溯字段完整。导出未补理财零钱产品；黄金没有通用产品代码字段。
- `transaction_visibility.go` 遮蔽部分名称和负债引用，但不会清空所有其他类型的内部 ID；新增字段不能直接序列化原交易对象。现 CSV 未使用名称 override，未知账户会回退为 ID；XLSX 必须独立执行历史遮蔽，不能复制这个回退。
- `frontend/src/api/client.ts` 的响应拦截器在下载函数捕获前规范化错误；`api/errors.ts` 同步读取 JSON 的业务码。Blob 错误必须在身份处理和错误规范化前解码，否则超限提示或终止会话业务码会丢失。
- 外层 `docker/nginx.conf` 和 `frontend/nginx.conf` 当前代理读取超时均为 60 秒。Go 服务和开发代理不需要为本次导出修改全局超时。

主规范已有基金、黄金、理财 CSV 的用途/产品识别要求；现实现的独立 CSV 列仍只有 13 个，产品信息可能仅存在于备注。本次不删除这些既有要求，也不借新增 XLSX 改写 CSV 列协议；XLSX 提供明确的结构化字段。已有 CSV 的产品识别情况由兼容回归观察，若发现不满足原规范，应另行记录，不擅自扩展本次列结构。

## Goals / Non-Goals

**Goals:**

- 复用现有筛选、排序和资金影响规则，让查询、权限投影与文件编码各自职责明确。
- 在开始文件响应前完成上限检查、关联验证和文件生成，使业务失败仍可返回标准 JSON。
- 对 10 万条采用有界读取和工作表流式写入；维持一次请求直接下载的模型，不承诺任意规模或机器上的固定完成时间。
- 保留 CSV 行为及现有会话刷新、终止、换号响应隔离。

**Non-Goals:**

- 不重构普通列表的所有关联补全，也不修改任何资金写入、估值或历史排序规则。
- 不把导出明细升级为持仓报告，不输出成本、份额、盈亏、分期账单明细或行情快照。
- 不生成可恢复备份、后台队列、下载链接、导出历史或共享文件。

## Decisions

### D1. 在既有接口显式选择格式，保留 API 默认 CSV

| 请求 | 行为 |
| --- | --- |
| 未指定 `format`、空 `format`、`format=csv` | 原 CSV 路径、13 列、BOM、`.csv` 文件名和现有 MIME |
| `format=xlsx` | XLSX 路径；MIME 为 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`；文件名 `transactions-YYYY-MM-DD.xlsx` |
| 其他非空值 | HTTP 400，现有 `CodeInvalidParams` JSON |
| XLSX 超限 | HTTP 413，`CodeInvalidParams` JSON，消息说明最多 100,000 条，建议缩小筛选或选 CSV |
| XLSX 生成超时 | HTTP 504，`CodeInternal` JSON，提示重试或缩小范围 |
| 查询/必要关联/文件生成失败 | 既有权限错误或 HTTP 500 标准错误，不发送附件头 |

格式在读取数据库前验证。两种格式复用相同的查询参数绑定和筛选构建；XLSX 不接受可扩大本人范围的 owner 参数。XLSX 成功响应设置附件文件名和 `Cache-Control: no-store`，不返回 JSON 成功包装。CSV 不新增行数限制或强制转码。

替代方案：新建平行路由需要重复参数处理；直接把旧路由默认改为 XLSX 会破坏已有调用。显式格式保留调用兼容，前端默认操作另行选择 XLSX。

### D2. 有界读取和一致读取视图

在仓储增加导出专用读取能力，沿用 `applyFilter` 和 `transactionOrderQuery`，由服务沿用 `CanView`、`personalFilter` 生成本人范围。XLSX 查询移除分页，最多取 100,001 条，用额外一条判断是否超限。命中 100,001 条即停止，不查询关联、不开始编码，不使用“先无界读完再判断”的路径，也不依赖可能与后续结果不同的单独 count。

仓储在一个只读、可重复读的数据库事务内读取受限流水、必要账户/分类元数据及关联。使用同一事务连接，相关记录和展示顺序来自同一读取视图；不锁住资金写入。先判断行数再补关联。读取全部完成后提交/结束只读事务，编码在事务外完成。普通写入路径和 CSV 的 `ListAll` 不受此读边界改变。

元数据读取使用 `AccountRepo.Metadata` 同类的纯元数据查询，不调用会计算估值的账户列表。避免每行查询：按关联类别去重并以有界批次读取，批次需遵守数据库参数数量限制；仓储错误一律返回服务。无需展开 `WealthCashFlow` 或补已退累计金额。

替代方案：对页面已加载对象生成文件会漏后续页；多次独立分页读取可能混入并发新增/删除；以金额或日期为游标也不适合本人自定义顺序。上限内统一读取视图更容易保证完整性。

### D3. 服务生成专用安全明细投影

新增 `TxnExportRow` 一类的内部投影，区分文件字段与数据库交易对象。仓储负责读取原始关联和归属证据，服务决定是否可输出及如何遮蔽；文件编码器只接收已验证的明细，不再查数据库或决定权限。通过明确的导出仓储依赖接入 `TxnDeps`，避免在编码器中断言具体数据库类型；保留原 `TxnStore`/CSV 路径的兼容性。

追加列固定为：

| 列 | 来源/语义 |
| --- | --- |
| 流水 ID | `Transaction.ID`，可见流水本身的稳定标识 |
| 关联原流水 ID | `RelatedTxnID`，仅输出经本人可见性验证的引用；不要求原流水也命中本次筛选 |
| 所属账期 | 已物化的 `PeriodKey`，不按现在的结算日重算 |
| 投资类型 | 基金、黄金、银行理财、理财零钱；其他记录留空 |
| 产品代码 | 基金完整 `ths_code`、理财 `wealth_products.code`、黄金 `GoldPosition.ProductKey` |
| 关联记录类型 | 券事件、基金事件、黄金事件、理财事件、理财零钱收益记录；无关联留空，受遮蔽时为历史关联 |
| 关联记录 ID | 对应类型的事件/收益记录主键文本，不混用不同表的 ID |

黄金产品通过本人事件和持仓读取并验证，当前产品键为 `ccb:personal-gold-accumulation:CNY`，出处 `backend/internal/ccb/client.go`；不解析中文备注或用当前报价替代身份。理财零钱由 `WealthCashYieldID` 关联收益记录和 `ProductID`，验证 `OwnerID`、`AccountID`、回指 `TxnID`；它不是 `WealthEventID`。无资金流水的零额收益、再投资和估值事件不增加导出行。券编号继续位于第 10 列，对应券事件放在追加关联列中；本次不额外增加负债计划或持仓 ID 列。

历史转账沿用本人范围规则：对方账户列直接输出「历史关联账户」，不回退其数值 ID；分类与全部追溯引用也要独立验证。合法历史不可见引用留空，并使用「历史关联」标识；正常本人必要关联的缺失、错配或数据库错误必须使 XLSX 失败。两种状态要区分，不把数据库失败当作历史遮蔽，也不查询他人私有资料填补空值。XLSX 不添加账户 ID 列。

金额继续调用现有 `Transaction.Effects()` 及类型、来源、用途标签，不从备注反推业务类型。金额列保留收入/退款正、支出/转账负；消费影响用于表达净消费。余额影响沿用交易行的既有定义，转入账户另列，不能宣称将其简单求和就等于本人总资产净变化。

替代方案：直接复用 `fillEffects` 补全结果容易隐藏读取错误和泄露原始引用；把所有业务事件展开为行会重复计数并扩大范围。采用一笔流水一行的专用投影。

### D4. 后端生成类型明确的单张工作表

新增后端 `github.com/xuri/excelize/v2`，实现放在 `service/txn_export_xlsx.go` 等导出文件；实现时固定兼容 Go 1.26.1 的稳定版本到 `go.mod/go.sum`。选择依据是其原生类型、样式和流式工作表能力，避免手写 OOXML 或在浏览器读取全部流水后编码。

- 首 13 列按原 CSV 顺序输出；追加 7 列，共 20 列（A:T）。只有「流水明细」工作表，无默认空白表、标题横幅或合计行。
- 日期按账务日构造无时区偏移的 Excel 日期值，显示 `yyyy-mm-dd`；不把本地午夜转 UTC 后造成前一天。
- 金额以原 `decimal` 的分精度值转换为数值单元格并显示 `0.00`，逐笔回读校验到分；保留现有正负和零影响。业务金额上限 `9999999999.99` 在当前模型范围内。
- ID、券编号、产品代码和账期显式为文字；备注、分类、账户、平台等原文本同样按文字写入，不使用 CSV 的前导单引号转义，也不设置公式或超链接。
- 冻结第一行；筛选范围为 `A1:T{数据行数+1}`，零结果为 `A1:T1`；使用适当的固定列宽，备注可换行。不创建需要至少一行数据的 Excel table，避免空表补出假记录。
- 使用 `StreamWriter` 顺序写行，在写行前设置冻结和列宽；样式复用而非逐格新建，完成后 `Flush`。筛选元数据使用与流式写入兼容的工作表配置方式，回读验证不能丢失或覆盖数据。
- 最终文件写到服务端唯一临时文件，完成后才设置响应头和发送，携带文件长度；成功、失败、取消均关闭工作簿及临时资源，并在发送结束后删除临时文件。数据库快照不跨越文件编码或传输阶段。

Excelize 官方文档说明流式行号必须递增、结束需 `Flush`，以及冻结/列宽需在写行前设置；实现依此执行，不混用普通方式重写同一工作表数据。[流式写入文档](https://xuri.me/excelize/en/stream.html) 与 [单元格类型文档](https://xuri.me/excelize/en/cell.html) 为实施参考。这里的流式写入是降低文件构造内存，并非提前开始 HTTP 文件传输。

替代方案：浏览器生成会增加前端依赖和内存压力，且难以与后端权限投影一致；手写 ZIP/XML 增加样式、类型和资源清理的维护成本。

### D5. 前端默认 XLSX，兼容错误与会话处理

流水页使用当前 Ant Design 按钮体系提供默认导出 Excel 的主操作，以及明确的「导出 CSV」选项；可使用分体按钮。桌面和手机共用，键盘、触控均可操作，不新增筛选表单。开始时捕获当前生效 `exportParams`，两种格式共用 `exporting` 和同步防重锁；排序保存进行中暂不可导出，避免本地未确认顺序与服务端不一致。

`exportTxns` 接收受约束的格式联合类型，显式传格式、`order=custom` 及原有 `txnQueryParams(p, true)`，按响应 MIME 与扩展名处理文件。成功时校验非 JSON 文件响应，再创建下载链接并释放对象 URL；失败不创建链接。CSV 保持 30 秒客户端超时，XLSX 使用 55 秒；服务端 XLSX 查询及生成设置 50 秒上下文预算，检查取消并映射标准错误，在现有 60 秒代理空闲超时内留出返回提示的余量。传输失败仍可能发生，应反馈重试而不伪称成功。

在 `api/client.ts` 的响应错误处理最前段，为请求 `responseType=blob` 且响应为 JSON 的情况解码 Blob，将合法业务体交回现有 `normalizeError` / `isTerminalAuth` 流程。解码前后均校验会话 epoch；不能在下载函数 catch 中才解码，因为该时原始 body 可能已丢失。成功分支若收到 JSON 也拒绝当作文件保存。继续使用共享 Axios 客户端的认证重试，不新建绕过拦截器的裸客户端。

下载前再次确认发起请求的 epoch 仍有效；页面卸载/退出时取消可取消的请求，迟到结果不触发文件下载。超限显示服务器的“缩小范围或 CSV”文案，用户自行选择 CSV，不自动重发。

替代方案：把每次导出都做成配置弹窗增加操作步骤；只延长客户端超时不能突破代理预算；下载 catch 才处理 Blob 无法保证认证业务码正确。

### D6. 验证分层

- 服务/仓储：复用 `txn_export_test.go` 的 `exportEnv`，覆盖筛选、关联退款跨月、自定义顺序和 0/100,000/100,001 边界；超限必须在关联和编码前发生。用 MySQL 事务集成场景验证读取视图一致性，模拟关联查询失败确认不会降级成功。
- 工作簿：通过 Excelize 回读，并在必要时检查 OOXML 单元格类型/公式、冻结和筛选范围。验证 20 列、日期数值、可计算金额、长 ID、前导零、特殊字符、空表，以及券、基金、黄金、理财和正负零钱收益的追溯/消费影响。
- 权限：复用个人资金范围、历史关联与各投资服务测试环境，覆盖四种角色、本人同名资源隔离及不可见引用遮蔽。
- HTTP：验证默认/显式 CSV、XLSX MIME/附件、非法格式 400、超限 413、超时/内部失败为 JSON 且无附件响应。
- 前端：有针对性验证 Blob 错误解码、401 刷新/终止业务码、换号隔离、防重和文件名，不为按钮文案或 JSX 结构建立镜像测试。
- E2E：扩展 `frontend/e2e/export.mjs`，原 CSV 检查改为显式选择 CSV；默认操作改验 XLSX，覆盖筛选、页码、viewer、手机和失败提示。用临时测试账本构造数据并验证导出不写账；CSV 使用可靠解析而非按换行拆行，XLSX 内容由后端工作簿测试校验，浏览器验证真实下载与界面。保留桌面/手机截图。
- 10 万条试验记录生成耗时、峰值内存和文件大小，检查完成在 50 秒生成预算内或返回明确超时；超过预算则优化有界批量查询/写入，不擅自降低已确认行数上限或新增后台任务。

## Risks / Trade-offs

- [10 万条仍占用数据库排序、DTO 内存和临时磁盘] → 限量 100,001 查询、批量关联、样式复用、流式工作表、50 秒取消预算和临时文件清理；实施时做一次实际规模测量。并发全局队列不在本次范围内。
- [历史内部引用泄露或把关联失败误当空值] → 专用安全投影逐类验证归属，区分合法遮蔽和数据错误，覆盖历史跨账号测试，不直接输出原交易对象。
- [Excel 数值精度/公式和日期偏移] → ID/代码用文本、金额按分回读、日期按账务日写入、所有用户输入只写文字。
- [CSV 与 XLSX 日后语义漂移] → 共享现有金额/标签函数和筛选排序，保留独立列模式与 CSV 基线；CSV 产品识别的原规范不被本变更弱化。
- [二进制错误破坏认证刷新或终止处理] → Blob 解码发生在规范化之前，覆盖刷新、终止、换号测试，不绕过共享客户端。
- [网络断开导致物理文件传输不完整] → 完成生成后才开始响应，声明文件长度；客户端下载失败不给成功提示，可重试，临时文件始终清理。无法把网络传输保证为原子操作。

## Migration Plan

1. 无数据库迁移。实现时新增固定版本 Go 依赖与导出代码，前端不新增生产工作簿依赖。
2. 先发布兼容旧客户端的后端，再发布默认请求 `format=xlsx` 的前端；核对代理既有 60 秒配置，部署不属于本轮规划授权。
3. 在专用测试环境执行 Go 检查、前端构建和桌面/移动端导出验收；确认旧客户端的无格式 CSV 调用未变。
4. 回滚时先恢复前端 CSV 操作，再回滚后端。无数据回滚或财务修正步骤；已经下载的文件不受代码回滚影响。
