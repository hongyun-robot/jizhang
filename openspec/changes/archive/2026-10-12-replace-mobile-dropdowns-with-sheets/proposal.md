## Why

移动端把搜索输入与下拉选项叠在表单里，会被软键盘挤占空间，滚动后也容易难以定位和点选。项目已有“平台 / 商家”底部浮层，但其搜索框仍自动聚焦，需要将这种选择交互推广到全部同类字段，并让用户主动点击输入框后才唤起键盘。

## What Changes

- 小于 768px 的手机视口中，全部普通选项下拉、可搜索下拉、自动补全选择器和级联分类选择改用“非输入触发器 + 底部选择浮层”；沿用现有平台 / 商家控件断点，768px 及以上保留既有桌面交互。
- 覆盖记账和转账账户、流水账户 / 分类筛选、券支付账户 / 状态、定时记账账户、账户信用类型 / 还款月份、全部负债操作中的账户 / 分类 / 账单 / 关联流水 / 分配方式 / 手续费方式，以及用户管理角色选择。
- 打开、加载、重试和再次打开浮层均不自动聚焦输入框；先展示已有选项，只有用户点击浮层内的搜索或名称输入框才唤起软键盘。平台 / 商家的现有自动聚焦一并移除。
- 账户、平台 / 商家、分类、账单和关联流水等目录提供顶部搜索；角色、状态、还款月份等短枚举直接点选。搜索词同时作为可创建字段的新名称候选，输入时浮层扩展以保留可用列表空间。
- 明确区分只选已有项与可创建新名称两种能力。平台 / 商家沿用现有创建能力；账户、分类、账单、关联流水、角色及固定枚举只允许选择已有项，搜索无结果时不提供创建或把搜索文字写入字段。
- 保留单选、当前值、清空、分类路径、字段校验、禁用和权限语义；浮层搜索词与已选值分离，取消不改值，明确选择后回填并关闭。平台 / 商家保留显式创建及手动名称随父表单保存的兼容路径。
- 共用浮层的布局、选项状态、焦点管理、嵌套层级和软键盘避让，并补充手机选择、创建限制、层级分类、失败恢复和桌面回归验收。

范围限定为选项选择类控件；日期 / 时间选择器、金额和备注等普通输入、现有分类磁贴、分段按钮及操作菜单保持原交互。

## Capabilities

### New Capabilities

无；共用现有界面交互与平台 / 商家选项目录能力。

### Modified Capabilities

- `ui-shell`: 规定手机选项选择统一使用底部浮层、主动输入才唤起键盘、创建能力明确区分、保留字段语义，并修订弹层挂载约束以兼容独立的手机选择浮层。
- `voucher-platform-options`: 平台 / 商家改为桌面输入下拉与手机选择浮层两种交互，明确搜索和字段值的边界，保留创建、手动输入、失败重试与历史值兼容。

## Impact

- 前端：新增共用选择浮层及响应式选择适配组件，迁移当前 29 处 `Select`、1 处 `Cascader`，让 `PlatformInput` 共用浮层；主要涉及 `frontend/src/components/`、`features/records/`、`features/recurring/`、`features/liabilities/fields/`、`pages/Accounts.tsx` 和 `pages/Vouchers.tsx`。
- 样式与基础设施：调整 `styles/mobile-controls.css` 中平台专用样式的复用边界，复用 `useVisualViewportKeyboard` 的监听；桌面继续沿用 `popupInParent` 定位。
- 验收：扩展 `frontend/e2e/` 的平台、筛选、键盘、用户与负债验收，使用本地独立测试账本，补充手机 / 桌面截图与实体手机键盘复核。
- 不新增后端 API、数据库迁移或前端依赖；现有 ID / 字符串接口、账户归属、角色权限和账务保存规则不变。
