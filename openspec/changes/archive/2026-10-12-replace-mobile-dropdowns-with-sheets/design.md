## Context

动机与范围见 `proposal.md`；行为契约见两个增量规范。

当前前端使用 React 和 Ant Design，扫描到 29 处 `Select`、1 处 `Cascader`。`PlatformInput.tsx` 已在 `Grid.useBreakpoint()` 的 `md` 以下使用按钮触发底部 `Drawer`，桌面保留 `AutoComplete`；手机搜索框存在 `autoFocus`，与用户期望冲突。其创建请求已有 `inFlight`、`generation` 和当前值保护，应复用而不是把业务请求复制到通用组件。

`popupInParent` 承担既有表单下拉与日期面板的局部挂载。主规范 `ui-shell` 的“弹层挂载于触发器”对全部面板要求局部挂载，`voucher-platform-options` 的“同一输入框内搜索和单选”要求输入下拉；这两条与独立手机选择面板冲突，已在增量规范中明确修改。

`useVisualViewportKeyboard` 已集中维护 `--kb-inset`，内部观察器引用计数支持多弹窗同时使用；现有键盘 CSS 主要照顾 `Modal`。`VoucherFormModal` 显式使用高于基础值的弹层层级，流水筛选已有底部 `Drawer`，因此新浮层必须处理嵌套覆盖，而不能只套一个默认层级的抽屉。

现有字段没有多选 / 标签输入。分类筛选使用 `categoryIndex` 生成的两级选项，有子分类的分组使用负数虚拟值，最终查询只接收真实分类 ID。还款月份存在合法数值 `0`，券状态存在合法空字符串 `''`，通用组件不能以 truthy 判断是否选中。

## Goals / Non-Goals

**Goals:**

- 让选择器只负责展示和明确选择，搜索草稿、持久化目录和父表单提交各有独立边界。
- 复用一套手机面板、焦点和视口处理，桌面保留每个字段的既有控件配置与回调。
- 调整后仍能由父表单定位校验错误，仍能由原有回调触发筛选、金额回填、角色修改或预览失效。

**Non-Goals:**

- 不为账户、分类或账单新增快捷创建流程，不新增最近使用排序、远程搜索接口或持久化搜索状态。
- 不替换日期选择器，不重做分类磁贴，不改变角色、归属、资金提交或草稿恢复规则。
- 不实现原生手机应用、全局表单引擎或完整的 Ant Design 选择器属性代理。

## Decisions

### 1. 使用可扩展的底部选择面板

默认结构为“标题与关闭入口 → 当前选择摘要 → 可选搜索框 → 已有选项 → 可选创建操作”。所有选项提供清晰选中标记。账户、商家、分类、账单与流水目录开启搜索；短枚举没有搜索框，直接显示全部可选项。搜索按已有标签 / 完整路径包含关系过滤并忽略英文字母大小写，不新增后端查询。

底部面板初始约为可用高度的 64%，短列表按内容缩短；主动输入时扩展到键盘上方可用区域，顶部保留小间距，列表内部滚动。面板随可视高度变化，不能把 `64vh` 固定尺寸当作键盘避让。关闭输入状态或键盘收起后恢复正常高度。

考虑的替代方式：

| 方式 | 适用情况 | 本次决定 |
| --- | --- | --- |
| 表单内展开选项列表 | 极短列表，表单空间充足 | 不作为通用方案，长列表会推移表单和底部操作 |
| 全屏选择页 | 很大的目录或复杂多步骤选择 | 本次采用浮层扩展，保持父表单位置和草稿，不引入选择路由 |
| 分类磁贴 / 单选按钮 | 分类快捷选择和两三项切换 | 保留已有磁贴与分段控件，不强制用于账户或商家目录 |
| 底部选择面板 | 表单中的单选、搜索与明确创建 | 本次采用，复用现有平台 / 商家的交互方向 |

以上选择是基于项目现有表单与目录的设计判断。默认不新增拖拽吸附档位，避免为完成单选增加手势和状态复杂度。

### 2. 分离共用面板与字段适配

新增共用 `SelectionSheet`，负责按钮触发器的共享外观、底部 `Drawer`、列表状态、搜索区域、明确操作入口和安全焦点。面板只接收候选项和事件，不持有业务 API 或父表单提交能力；创建能力通过显式可选配置提供，缺省没有创建操作。

新增 `ResponsiveSelect<Value extends string | number>`：

- `md` 以下使用共用面板，`md` 及以上继续使用原 `Select`。
- 接收当前值、候选项、显示标签、纯文本搜索标签、字段标题、清空权限、禁用 / 加载 / 错误状态，以及原有 `onChange`。只支持本项目实际使用的单选场景。
- 手机搜索开关独立于桌面 `showSearch`，让现有不可搜索的账户下拉在手机也可以搜索，桌面配置保持。
- `id`、表单关联、错误状态和可聚焦的触发器引用贯通，兼容 `Form.Item` 注入、错误定位和手写表单校验。选择仅发出原标量值；不做 ID 字符串化。
- 有值判断使用 `undefined` / `null`，不误丢 `0` / `''`；清空只发出原字段期望的空值，不增加原字段没有的清空能力。
- 当前值暂未出现在异步选项中时保留原值和可用标签，不在加载完成时挑首项。原字段传入的账户、账单和权限过滤仍在调用方执行。
- 父级可通过 `active` 或受控关闭信号结束会话；`Modal` / `Drawer` 关闭后即使子组件仍挂载，也不保留浮层。
- 实施验收确认父弹窗关闭时会冻结其内容，单靠子组件的 `active` 属性无法保证收到关闭信号。父 `Modal` / `Drawer` 外包裹 `SelectionScope`，以共享 React Context 向普通选择、分类和平台选择器传递活动状态；父内容冻结时也能关闭浮层、停用目录读取并使创建回填会话失效。

`PlatformInput` 保留目录查询、名称校验、独立创建、提交锁和迟到响应守卫，仅将手机呈现迁到共用面板；桌面的 `AutoComplete` 不经过普通单选适配器。

不选择全局覆盖所有 `Select` 的配置或 CSS：每个字段的清空、值类型、禁用和回调不同，CSS 也无法正确表达创建能力。

### 3. 搜索、选中与创建使用独立状态

| 事件 | 搜索草稿 | 父字段 | 目录请求 / 父提交 |
| --- | --- | --- | --- |
| 打开 | 重置为未过滤 | 保留 | 按既有查询读取，不创建、不提交 |
| 输入 / 清除搜索 | 更新 | 保留 | 只过滤候选项 |
| 选择已有项 | 清理并关闭 | 回填原类型值 | 原有选择回调执行一次 |
| 允许清空的字段点击清空 | 清理并关闭 | 发出原有空值 | 原有清空回调执行一次 |
| 确认创建平台名称 | 保留到请求成功 | 成功且会话仍有效时回填 | 调用现有目录创建，不提交父表单 |
| 取消 / 关闭 / 浏览分类分组 | 清理或仅更新浏览层级 | 保留 | 不创建、不提交 |

“新名称可创建”只在平台 / 商家开启，沿用首尾空白处理、128 个 Unicode 字符上限、完全相同名称复用和现有共享目录接口。包含搜索可以忽略大小写；判断完全同名和创建去重保持现有规则，不能合并 `JD` 与 `jd`。

正常流程以“创建「名称」”为新名称的主操作。为保持现有失败时仍能填写文本并随父表单保存的契约，目录读取或独立创建失败时，平台浮层额外显示“使用此名称”，辅以“填写到表单，保存时加入目录”说明。此动作仅明确回填有效文本，不单独调用创建接口；只选型字段不提供此回退。正常状态不摆放两个并列新建动作。

创建中的重复点击受原 `inFlight` 保护，显示实际进行中状态。关闭浮层、父级结束、编辑对象切换或之后修改输入都使当前回填会话失效；迟到成功可更新共享缓存，不改当前字段，不重开浮层。键盘 Enter 仅在明确选中操作时确认，输入法组合态和 Tab 不触发创建或父表单提交。

### 4. 分类使用同一浮层但保留路径

流水筛选的 `Cascader` 通过轻量响应式分类适配器接入共用面板，桌面保留现有 `Cascader`：未搜索时展示一级分类，点击分组后展示子项并可返回；搜索时显示末级结果和完整路径，避免同名子项歧义。无子分类的真实一级分类仍可直接选择。

复用现有 `CategoryOption` 与 `categoryPath`，分组虚拟负数只用于浏览，不发给筛选 API。明确选择仍生成原路径，让 `FilterControls` 保持取路径最后一个真实 ID 的逻辑；清空保持原清空事件。搜索、返回一级和取消不调用筛选 `patch`。

把所有分类直接压成没有路径的字符串虽然实现较短，但会丢失层级与同名区分，因此不采用。已有 `CategoryPicker` 分类磁贴继续保留。

### 5. 手机断点、弹层层级与焦点统一

选择器使用与当前 `PlatformInput` 及键盘 / 控件样式一致的 `<768px` 断点；应用导航仍在 992px 切换。这是选择控件断点与导航断点各自延续现状，768–991px 不新增一套选择行为。跨断点关闭旧面板并保留字段值，避免残留遮罩与双重焦点管理。

共用浮层使用独立覆盖层挂载，层级从当前父弹窗层级派生，必须高于登记券的高层 `Modal` 和流水筛选 `Drawer`；不把浮层挂在会裁切内容的表单容器，也不使用任意全局极大层级。父层保留自身滚动位置和草稿，最上层只接受当前面板的点击与关闭事件。

打开时把焦点放在带 `tabIndex=-1` 的面板标题，关闭后回到仍存在的按钮触发器；显式移除手机搜索框 `autoFocus`，也不在动画回调、选项刷新或重试中调用输入框的 `focus()`。标题焦点与关闭后的触发器焦点符合 [W3C 模态对话框焦点建议](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。保留对话框命名、可见关闭按钮、Tab 焦点约束和 Escape 关闭最上层的行为。

复用 `useVisualViewportKeyboard(sheetOpen)` 的引用计数监听，以当前可视区域约束浮层的底边和高度，使用共享键盘 inset 时防止浏览器已经收缩布局后的重复扣减。搜索框与标题不滚动，选项区 `min-height: 0` 并内部滚动；安全区、16px 手机输入字号、44px 以上选项热区和现有明暗主题 token 均统一处理。普通字段选择、关闭或创建成功后搜索输入失焦，不跳回父表单金额框。

## Risks / Trade-offs

- [手机键盘行为无法由桌面自动化完全重现] → 浏览器验收检查打开 / 加载 / 重试后没有文本焦点并模拟可视区收缩，另以 iOS Safari 和 Android Chrome 实机复核键盘、选项点按与恢复。
- [嵌套 `Modal` / `Drawer` 层级或焦点冲突] → 在高层券表单和流水筛选抽屉内覆盖选择、取消、遮罩、Escape 与焦点返回，确认只关闭顶层且父层不响应点击。
- [通用组件吞掉 Form 注入、零值或原有回调] → 验收角色即时修改、数值零、空字符串、清空、校验定位，以及消费 / 费用选择后的原有回填和预览更新。
- [目录重取或创建迟到覆盖新草稿] → 保留业务层原有守卫并加入浮层会话关闭信号，覆盖取消后成功、换对象与后台刷新。
- [读失败被误显示为空列表] → 分别展示读取中、真实空目录、无匹配和读取错误；保留已有缓存、字段值、查询词和重试入口，只在平台字段提供手动名称回退。
- [两个响应式断点可能造成误解] → 明确本次沿用选择控件 768px，不更改导航 992px；检查 767 / 768px 和 991 / 992px 两组边界。

## Migration Plan

1. 先加入共用面板、样式与普通单选适配，迁移平台组件并消除自动聚焦。
2. 按清单迁移全部普通下拉和分类级联，逐处保留原值类型、禁用、清空和回调；不通过 `App` 全局配置绕过字段契约。
3. 在本地独立浏览器 fixture 验证选择与资金 / 权限相关回归；改用角色、名称和选中状态定位，桌面专用 `.ant-select` 定位仅保留在桌面分支。原平台测试的 897px 视口继续走桌面，390px 分支走手机浮层。
4. 执行前端类型检查与生产构建，记录手机 / 桌面明暗主题截图及实体手机检查结果。实施完成后按正常发布流程上线；本提案不执行部署。
5. 本次没有数据迁移。回滚时恢复本次前端组件与样式，既有字符串 / ID 接口及共享目录数据不需要回滚。
