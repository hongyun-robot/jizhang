# add-vouchers 验证记录

验证日期：2026-10-10。本变更仅在本地实施与验证，未部署生产。

## 后端

- `go test ./...`：通过，包含普通流水、退款、周期模板、统计、预算、封账及新增券用例。
- `go vet ./...`：通过。
- 真实 SQLite 覆盖：购券扣余额、跨日/跨月/自定义账期核销、实付与分角分摊、零分份额、剩余退款、作废、逆序撤销、自动退款撤销后暂停、权限、封账、请求幂等、事务回滚、失败隔离、停用账户恢复、未用汇总、CSV、负债账户与时间边界。
- HTTP 验证：有效期默认开关、四角色、400/403/404/409、普通接口拒绝伪造用途/直接改删/重复退券、自动处理及 DTO。

## MySQL

使用临时解包启动的 MySQL 8.0.46。测试自动创建并清理独立数据库；未使用现有账本。

- 空库顺序迁移及从 `000004` 升级 `000005`；存量金额、日期、归期和普通用途保留。
- 无券数据 down/up 成功；有券数据 down 被 CHECK 拒绝，券和账户数据保留。
- 双服务实例并发自动退款，只生成一笔有效退款。
- 核销/退款竞争不重复结算；金额与次数守恒。
- 封账/财务写入竞争按提交顺序协调，封账后的写入拒绝。
- UTC 服务器/驱动下购券日期和有效期不提前，自动退款仍归属北京时间有效期次日。

## 前端

- `npm run build`：通过，TypeScript 与 Vite 构建成功。
- `node e2e/vouchers.mjs`：通过，Firefox 桌面 1440×1000、手机 390×844。
- 100 元 5 次券：购买余额减 100、消费不增加；核销 2 次消费加 40、余额不变；退剩余 60 余额回升，消费仍为 40。
- 验证退款、作废、核销撤销后的统计与余额，删除未使用券恢复购买余额。
- 10 元 3 次券：3.33、3.33、3.34，累计消费恰为 10。
- 自动退款撤销后重新打开应用保持暂停与剩余份额。
- CSV 保留原金额列，增加用途/券编号/余额影响/消费影响，最后份差额可导出。
- 只读成员可从“我的券”查看，无写按钮、撤销按钮或券 ensure 写请求。
- 浏览器无页面错误；已修正新增控件弃用提示和图标按钮可访问名称。
- `node e2e/voucher_retry.mjs`：通过。模拟服务器已提交购券但返回 504，修改金额后重试仍使用原请求标识、得到 409，只有一张券和一次扣款，清理后余额恢复。

## 已知边界

券的自动退款为用户配置驱动的记账；未查询平台到账。普通退款继续冲减消费，未用券退款不冲减消费。封账、停用账户阻塞时保留待处理份额，不跨期迁移或自动解封。第一版退款为全部未用部分、撤销按逆序，生产降级需遵守 README 的回滚约束。
