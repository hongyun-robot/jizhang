## Why

分类、账户和平台 / 商家管理都需要把常用项放到前面，但目前只能在账户表单中手填排序值，分类没有排序交互，商家按名称排列。建立统一的拖动排序能力，可让手机与桌面使用相同操作，并让管理页与记账选项保持一致。

## What Changes

- 建立可复用的目录排序交互及保存协议：专用拖动手柄、鼠标 / 触控 / 键盘操作、拖动结束自动保存、失败恢复、并发冲突提示和登录会话隔离。
- 分类管理支持分别拖动支出、收入一级分类；点击大类打开子分类管理弹窗，在弹窗内拖动同一大类的小项，并保留新增、重命名及删除能力。只调整同级顺序，不通过拖动变更父分类或收支类型。
- 账户管理的手机列表和桌面表格支持拖动所有本人账户，包含现金资产、基金资产、负债及停用账户；以拖动替代界面上的手填排序值。
- 平台 / 商家管理支持拖动完整目录；有搜索条件时保留搜索与维护，清空搜索后可排序，避免过滤结果覆盖完整目录。
- 保存后的顺序持久化到本人目录，刷新、重登、换设备后保持；分类、账户及商家业务选择器按保存顺序展示符合各字段约束的选项。
- 新条目默认追加到所属列表末尾；重命名、普通编辑、停用及同名商家复用保留顺序。修复分类重命名遗漏 `sort` 会重置位置的问题。
- 使用一次事务批量保存顺序，校验完整列表、所属账号与分类作用域，避免逐条请求造成部分成功或旧列表覆盖新结果；排序不产生资金变化。

## Capabilities

### New Capabilities

- `catalog-ordering`: 个人目录通用排序的操作、持久化、批量原子性、冲突恢复、会话隔离及选项顺序契约。

### Modified Capabilities

- `categories`: 一级分类排序、点击大类进入子分类管理弹窗、同父子分类排序及分类选项顺序。
- `accounts`: 统一账户目录拖动排序、移除手填排序入口、业务过滤后的相对顺序及编辑保序。
- `voucher-platform-options`: 商家顺序持久化、管理搜索与排序边界、选项同步及个人目录维护保序。

## Impact

- 前端：新增共享排序组件 / Hook 与纯顺序工具；接入 `Categories.tsx`、`Accounts.tsx`、`Platforms.tsx`，调整 `AccountEditor.tsx`、`PersonalLiabilityAccountModal.tsx`、目录 API、`platformCache.ts`、相关类型和样式。复用现有 React Query 及 auth epoch 机制。
- 后端：分类、账户及商家分别增加批量排序接口，共用顺序校验与事务内排序写入机制；调整创建时的默认顺序与更新时的省略字段语义，保持既有单条 CRUD 和业务字符串接口兼容。
- 数据库：复用 `categories.sort` 与 `accounts.sort`；在个人平台目录迁移 `000015` 基础上新增成对迁移，为 `voucher_platforms` 增加 `sort` 并按升级前顺序回填，增加按个人作用域保存成功排序请求的结果表。个人目录归属、历史名称、余额和引用不变。
- 依赖：拟采用 dnd-kit 当前 React 包并封装在共享层；实施时固定与 React 19 / TypeScript 兼容的版本及 lockfile。
- 验证：补充权限、批量回滚、重试与并发测试，MySQL 排序迁移和事务集成测试，以及桌面 / 手机 / 键盘浏览器验收。现有个人目录与平台管理验收作为回归检查。
- 本次交付为 OpenSpec 规划文件；功能代码、迁移执行和部署由后续 apply 工作处理。
