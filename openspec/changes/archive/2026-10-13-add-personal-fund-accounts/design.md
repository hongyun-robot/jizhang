动机见 proposal.md；行为契约见本变更的六份 delta spec。实现必须基于当前工作区已有的个人账户、负债和前端修改，不能覆盖用户未提交工作。

当前约束：

- `accounts.type` 在 MySQL、Go、TypeScript 中只有 asset/liability。`AccountRepo.List` 用期初加流水聚合余额，`Dashboard.tsx` 直接相加个人账户余额；`StatsService.Assets` 独立从期初及逐日流水重建曲线，不能只修改首页。

- `main.go` 已有 robfig/cron 生命周期、启动补处理及统计缓存失效钩子；当前没有基金任务。`config.go` 和 Docker api environment 白名单未接入 `FUYAO_API_KEY`。
- 扶摇在 2026-10-13 的授权实测中正确解析 `023564.OF`，返回 10 月 9 日净值 1.2305、10 月 12 日净值 1.1946。资料中的名称是“上证A”，区间收益的 timestamp 为 0。这些是接口观察，不能硬编码为业务数据。

已确认的产品决定：多基金账户；记录实际已完成交易与两类分红；全员本人配置，资金操作沿用既有角色；从建账起点记录个人历史；场外人民币净值型；加权平均成本；投资收益及费用完全独立于日常收支；样例只用于测试，实际数据由用户添加。

## Goals / Non-Goals

**Goals:**

- 保持现金、负债原计算路径兼容，用同一基金估值读模型支持当前余额与历史资产曲线。
- 财务事件可重放、可按末笔撤销，并在资金、份额、成本、封账和账号归属上原子一致。
- 行情是可共享的公开输入，个人交易与历史是本系统保存的事实。每日收益由这两类输入计算，不依赖外部个人资产授权。

**Non-Goals:**

- 不接券商或基金销售平台下单，不读取用户外部个人持仓，不维护待下单、撤单等订单工作流。
- 不实现货币基金万份收益、场内市场价格、外币换算、税务报表、自动分红入账或对未知类型的自动鉴别。
- 不把当前份额或当前净值应用于建账前个人历史，不将扶摇原始数据示例当作测试以外的真实持仓。

## Decisions

### D1：基金作为资产子类，独立持仓与行情模型

保留 asset/liability 顶层类型。新增仅对资产有意义的 `asset_class`（cash/fund）；旧资产迁移为 cash，负债为空，旧 API 创建未给子类时仍创建 cash。基金账户 `opening_balance=0`，通过期初持仓开账。

建议持久化结构：

| 结构 | 职责与关键约束 |
|---|---|
| `fund_instruments` | 公开完整 thscode 唯一、ticker、源简称、场外标的类别、元数据时间及同步状态；不能按名称合并 |
| `fund_positions` | 个人基金账户、标的、已确认估值口径及其确认人、当前事件版本与持久化重建标记；期初日期、份额及成本由事件重放；唯一 `(account_id, instrument_id)` |
| `fund_events` | opening/buy/redeem/cash_dividend/reinvest/settlement、本人归属、创建人、实际份额与金额、费用、生效/权益/资金日期、撤销状态；分红权益和有效到账引用唯一 |
| `fund_mutations` | 成功请求的不可变摘要与事件回执；唯一 `(owner_id, request_key)`，更正或撤销不覆盖先前请求的回执 |
| `fund_navs` 与报价修订记录 | 当前有效单位净值按 `(instrument_id, nav_date)` 唯一，保留 revision、获取时间及先前版本；adj 只作参考 |
| `fund_valuations` | 当前有效持仓快照按 `(position_id, nav_date)` 唯一；保存份额、成本、市值、日盈亏可用性、前一净值日期、事件版本与两端报价版本，旧修订可追溯 |
| `transactions.fund_event_id` | 受基金事件管理的现金转账关联，生成一笔或多笔时分别有唯一的事件/资金用途约束，避免客户端重试产生重复现金记录 |

行情数据无个人归属；持仓、事件和估值通过基金账户校验 owner_id。外键及服务端检查必须使事件不可能关联其他人的现金账户。派生投影可重建，不能通过通用 PUT 更新份额或成本；公用行情缓存不包含用户份额。

金额沿用 CNY 两位小数及现有金额上限。份额/净值输入、存储至多八位小数；未结转成本和期初数量乘成本价用 DECIMAL(36,16)，不先舍入每次单位成本再反乘。最终货币展示和资金流水舍入两位，API 输出十进制字符串，拒绝非有限数和聚合溢出。公开 JSON 用精确数字读取，不先经过 float64。

替代方案：增加第三种顶层 type 会影响所有资产/负债分支；把基金当普通余额账户会使买入本金、市值和普通支付权限混在一起。资产子类加独立持仓读模型使这些边界可测试。

### D2：两个时间轴与受管理的现金投影

交易表单记录的是平台已经完成的明细，不调用外部交易接口。`effective_date` 表示按实际成交/份额明细确定的经济生效日，`cash_date` 表示实际付款或到账日；确认时间另作元数据，不用请求提交日推断经济日期。分红还保留权益登记、除息、付款或再投资份额生效日期，权益登记日用于核对，真正改变权益的日期参与封账校验。

买入、赎回、现金分红在实际现金日期生成已有 `transfer` 类型，并使用 `fund_purchase`、`fund_redemption`、`fund_dividend` 用途；所有资金金额为正，创建人为当前用户。投资费用进入基金事件，不生成普通 expense；再投资和自动净值更新不生成普通交易。

基金账户的待结算现金读模型为：受管理转账的基金侧现金净额，加买入生效时的总投入消耗、赎回生效时的应收净额、除息时已确认分红应收、再投资生效时的应收转换等事件资金效果。它仅解释事件跨日期状态，不提供普通消费或自由支付余额。

| 已完成事件 | 持仓/成本生效 | 现金与等待结算 |
|---|---|---|
| 买入 | 增加确认份额，成本增加总投入 P（含费用 F） | 银行在付款日转 P 至基金；生效时基金结算现金消耗 P，转换为按净值估值的份额。若付款早于生效，间隔保留 P；若经济生效先于实际付款，未付义务作为有符号待结算额处理，不允许资产虚增 |
| 赎回 | 减少确认份额及比例成本，确认实际应收 B=成交金额−费用 | 生效日形成待收 B，到账日由基金转 B 至银行卡，等待期间保留 B，不再保留已赎回份额 |
| 现金分红 | 除息/权益生效日确认分红 D，原成本保持 | 生效日形成应收 D，付款日向银行卡转 D；基金净值除息下降与应收对应 |
| 红利再投资 | 确认分红 D；份额生效时增加实际新份额与成本 D | 生效至再投资确认间保留已确认分红应收，转换后消耗应收，没有第二次银行卡资金流 |

基金余额只取“有效份额市值＋待结算资金”，不再加 accounts 的普通转账聚合余额。银行等 cash 账户继续用旧转账聚合；这保证付款、确认、赎回、到账的每个历史日期都不重复或漏掉资本。

实际赎回或现金分红尚未到账时可以省略现金日期。以后登记到账使用独立 `settlement` 事件，引用原事件并记录现金日期和本人账户，不修改已经封账的原经济事实；金额由服务端取原应收净额。有效到账引用唯一，撤销末笔到账清除该有效唯一键并恢复应收。到账检查其自身日期；资金回执仍只生成一笔关联转账。

期初是已确认份额和成本的基准。追加事件的经济、权益及现金日期不能早于该期初日期，避免将已含在期初中的交易再次计入；补齐更早历史前先合法更正基准并处理后续依赖。

公开分红接口仅生成核对提示；个人实际选择、权益份额与金额由有权限者登记。同一次权益事件不能通过不同请求键重复登记或切换方式重复领收益，事件的业务唯一标识还需绑定持仓、权益日期/来源记录。未确认的除息相关日盈亏标为待核对，不能将真实分红选择默认为现金或再投资。

替代方案：只存确认日资金会改写银行卡真实日期；把到账作为收入会混入日常收支且可能重复确认已有收益。两条日期轴和受管理转账复用既有现金账务，同时保留结算过程的价值。

### D3：加权平均成本与统一盈亏计算

令 Q 为当前确认份额，C 为未结转成本，N 为单位净值：

```text
期初 C = 初始确认份额 × 用户输入单位成本价
买入后 Q' = Q + 新份额；C' = C + 总投入（含买入费用）
部分赎回结转成本 K = C × 赎回份额 / Q
赎回后 Q' = Q − 赎回份额；C' = C − K
赎回已实现盈亏 = 赎回净额 − K
全部赎回 K = 全部剩余 C；Q' = 0；C' = 0
持仓市值 M = Q × N；未实现持仓盈亏 U = M − C
累计投资盈亏 = U + 累计已实现赎回盈亏 + 已确认分红
```

费用展示是说明项：买入费已进 C、赎回费已进净额，不再扣一次。现金分红不减少 C；再投资按 D 增加成本和实际确认份额，因此分红只确认一次。期初成本由用户平均价格估算，界面与返回数据标明其来源，不能宣称包含未知历史交易的精确已实现盈亏。

持仓层相邻已公布净值区间的净损益使用两端真实 M 与生效交易重放结果：市值差，减区间生效买入总投入，加赎回应收净额，加权益生效分红；再投资的内部投入与分红各入一次、互相抵消。无事件时退化为 `Q × (N_new − N_prev)`。账户层用账户价值差减外部净资金流及新导入期初资产核对，结算日的内部转换不能成为收益。期初导入不是已赚的当日收益；若区间起点没有合法持仓基准，日盈亏为 null 并给原因。上游若缺中间真实净值，用可核对区间及明确区间标签，不声称多个日历日都分别有零收益。

事件以经济日期和稳定顺序重放。历史补录须校验后续全部余额/份额非负且全部受影响财务日期未封账；首版修改交易采用末笔撤销再登记，有后续成本依赖的早期事件直接拒绝。版本变化使相关投影失效，重算不会生成第二笔现金转账。

固定测试向量：初始 Q=5028.62，成本价 1.4119，N=1.1946，显示 M=6007.19，C≈7099.91，U≈−1092.72，收益率约 −15.39%；只有测试持仓起点不晚于 2026-10-09 且区间无事件时，1.2305→1.1946 的净值区间收益才为 −180.53。实际用户今天建账不能据该向量伪造昨日持仓。

替代方案：采用当前份额乘历史涨跌会在追加买入和部分赎回后出错；摊薄成本会把已实现收益或分红转进剩余成本。用户已选择加权法，保留两个收益维度便于核对且避免卖出时再加一次总收益。

### D4：报价适配器、边界确认与安全配置

新增独立 HTTP 适配器（建议 `backend/internal/fuyao`），通过可注入的 `FundMarketData` 接口向 service 提供标准化资料、单位净值和分红元信息；真实请求用 Go 标准客户端，测试替换为本地 HTTP stub。只发送代码与查询窗口，不发送用户数量、成本、账户或交易。

已核对的端点：[标的检索](https://fuyao.aicubes.cn/docs/api-reference/ticker-search/)、[资料](https://fuyao.aicubes.cn/docs/api-reference/fund-profile/)、[净值](https://fuyao.aicubes.cn/docs/api-reference/fund-performance/)、[分红](https://fuyao.aicubes.cn/docs/api-reference/fund-corporate-actions/)。检索按完整字符串保留前导零，用完整 `.OF` 标识和 fund-otc 结果消歧，禁止自动补市场后缀后直接视为成功匹配。净值取 `nav_type=unit`，不传 range 只会拿最新一条，不能支撑历史或日盈亏；冷启动按所需历史使用提供的 range，通常 fyear 覆盖首次基准，日常取 month，较长中断再取 fyear。接口可用历史不足时明确缺失，不能杜撰旧价格。

持仓保存 `valuation_basis=cny_otc_unit_nav` 和本人确认记录。名称简写可由用户设置私有显示别名，仍保留公开原名称与代码。提供方 category/currency 仅作元数据参考；首版不自动识别货币基金或真实外币币种，登记表清楚显示适用口径，已知不适用的标的或用户选定的不适用口径直接拒绝。

`FUYAO_API_KEY` 只从服务端运行进程环境读取；`.env.example` 给空占位，docker-compose api environment 显式注入。当前实测 Key 位于 Windows 用户环境、未在旧进程环境中出现，README 必须说明启动 shell 读取用户环境后再启动 API/Compose，避免误以为既有进程和容器自动继承；不把密钥复制到跟踪文件，不输出其值。缺 Key 时普通记账服务照常启动，基金同步标记未配置，已有行情仍可查询；新的非零持仓没有有效缓存价格时保留草稿、拒绝确认。

HTTP 设置超时、响应体上限、有限并发及同源重定向限制，禁止携带 Key 跳转到未知域。必须同时检查 HTTP 与业务 code，HTTP 200 的认证/权限错误也算失败。只接受正的有限单位净值与有效上海日期，不接未来日期；乱序或重复序列按日期整理，旧报价不覆盖 latest 指针。日志只记录代码、request_id、状态与安全错误，不记录头、配置或原始含密钥响应。

替代方案：客户端直连会泄露 Key 并产生跨账号重复抓取；加入 CLI/Python/MCP 增加运行依赖。服务器 HTTP 适配器便于限流、共享缓存和故障模拟，已足够支撑当前用途。

### D5：全账号后台同步与幂等快照

在现有 cron 中使用显式 Asia/Shanghai：周一至周五 19:00、19:30 至 22:30 每半小时检查，23:00 最后检查一次；次日 04:00 独立补查前一工作日，周五对应周六 04:00。工作日按周一至周五定义，节假日没有新报价则当晚到 23:00 结束。移除全天间隔配置。启动仅在对应时段恢复自动检查，其他时段使用缓存修复派生数据。首次持仓所需的冷取价和用户手动刷新仍保留，GET 不触发外部请求。

停止条件按完整基金代码独立保存：获得比检查前更新的最新报价（日期或最新报价版本变化），或缓存已具有当日报价，且估值计算完成后，记录当晚完成日期，不再检查该基金。其他基金仍等待自己的更新。未更新的代码每半小时最多自动尝试一次，23:00 后结束；完成日期和凌晨尝试日期持久化，重启、多 worker 不重复。04:00 对前一工作日最多发起一次补查，即使前晚已经完成也检查可能的延迟公布或修订，失败亦不自动追加凌晨重试。凌晨启动恢复窗口为 04:00–04:29，仍只进行该次补查。

扫描持久化的非删除持仓，正份额、待处理权益及有历史价格缺口的代码去重。停用基金账户不等于卖出，仍有份额时继续取价；零份额已结清的历史不需要持续抓最新价格，但必须能补齐必要历史。根任务不使用 HTTP 当前用户范围；只读重估按各持仓保存的归属构造结果，客户端只能获得本人资源。

对每个代码使用短租约/互斥和持久化最后尝试时间抑制重复 fetch，可复用已有 Redis；行情和估值正确性最终由数据库唯一约束、版本比较及原子更新保证。网络操作在财务事务外完成，限流、超时、空结果和单项失败隔离；429 或 code=4001 指数退避并限制立即手动刷新，初始可用值和最新日期不被异常覆盖。接口无新净值不生成新的收益日。source 同日期值发生修订才递增 revision、保留旧值，并重算受影响快照及区间，不能累加收益到余额。

同步只写行情及派生估值，不生成个人分红资金、不进入 `LedgerWrite` 长锁。持仓事件版本与快照输入版本校验防止报价更新与买卖并发产生旧份额的新价格结果；发现版本冲突重试派生计算。后台不得跳过已停用用户/账户的资源校验并写资金事件。

事件提交在同一财务事务标记 `rebuild_pending`，快照重建锁持仓、读取一致输入并原子清除标记。若提交后派生计算失败，成功资金回执仍不可变；后续后台或历史读取使用缓存报价重试，即使份额已清零或行情不可用也能修复。历史重建失败不能悄悄发布旧版本，某持仓失败不阻断其他持仓。报价修订后重建全部同代码持仓并失效统计缓存。

替代方案：每日固定单次抓取会错过延迟披露，必须等第二天才能恢复；每个用户各自任务会重复取同一行情。定时检查加按代码共享补齐能支持每日更新并避免承诺固定披露小时。

### D6：财务原子写入、角色与封账

新增 `FundService` 与基金仓储；业务计算放服务层、持久化和约束查询放 repository。创建、买卖、分红、期初更正与撤销在 `LedgerWrite` 内锁持仓及请求键，先验证当前用户、账户归属、角色、请求摘要和所有受影响财务日期，再生成关联转账、更新事件版本和投影；失败全部回滚。已存在的相同成功请求先按所有者与摘要匹配返回原结果，即便重试时该期后来封账，也不产生新写入；新写入仍执行封账限制。

基金的资金事务复用 `TxnService` 已有受管理写入方式，但只由基金服务传入可信事件上下文，不能给公开普通记账请求一个 bypass 标志。通用流水新增、改删、退款和所有普通资金选择器都禁止基金账户；事件转账的通用改删也禁止。服务端覆盖还款、购券、周期模板、费用来源等直接提交路径，不能仅过滤前端列表。

全员可建基金账户及合法期初；只读不能执行 buy/redeem/dividend/reinvest/undo。普通成员事件修改资格继承创建人权限；管理员仍须所有资源归本人。期初字段修改只在尚无后续交易且全部相关期间未封账时执行并留审计，已有事件不能通过直接编辑账户或持仓改成本。

市场价格缓存与派生估值不受收支封账硬锁阻断；其修订保留来源版本与界面标识，不改变封账收入、支出、流水或成本。基金财务日期跨期时检查每一实际生效及资金日期，不能只检查当前录入日期。

替代方案：将报价也写成交易会受封账阻断且污染生活收入；将份额更改绕过资金事务会出现扣款与持仓不一致。公开市场输入与财务事实分层能保留两类约束。

### D7：总资产与资产曲线共用估值读模型

提供只读 `FundValuationReader`，接受已验证属于账号的基金账户 ID 和截止日期，按截止日期重放持仓/待结算状态、取不晚于该日期的有效价格，返回市值、待结算额、已知性、报价日期和状态。当前余额和历史曲线都调用它；不能循环依赖写服务，也不能用列表当前 balance 重建过去。

`AccountRepo/ListFor` 普通聚合保持 cash 和 liability 的既有金额；基金资产用专属值覆盖，忽略普通 opening+transfer 聚合的基金侧数值。首页仍通过本人 `/accounts` 的 balance 求总资产，增加基金状态摘要与详情入口，金额口径唯一。已有未 scoped 的 `AccountService.TotalAssets()` 不作为新的个人入口，使用本人范围的聚合接口。

`StatsService.Assets` 中基金账户按日期替换为专属估值，不再在基金余额上累计 `DailyAccountNets`；现金端转账则仍进入原曲线。建账前该持仓价值为零；建账后价格缺失的点显示未知/曲线缺口，返回可识别的 incomplete 与可空金额，不悄悄置零或用未来价格。现有无基金用户的输出与旧金额保持一致。多只基金不同净值日期需逐持仓保留，账户汇总不能声称所有持仓都已更新到最晚那个日期。

行情/事件更新后使基金、账户、个人统计缓存失效，可先复用后端 InvalidateAll，缓存 key 继续包含 user ID。前端增加 funds query keys 和失效组；首页账户及基金详情采用有限轮询、回到页面/窗口聚焦刷新，正常后台变化约一分钟内可见。所有草稿、mutation 和迟到响应复用 scope、submissionGate 和存活检查。

替代方案：给首页另加一个基金市值字段但不改 `/accounts` 会造成首页、账户管理和资产曲线口径不一；把历史曲线用当前份额乘所有价格会违背建账起点和买卖日期。

### D8：API 与界面边界

建议 REST 入口均在现有 `/api/v1` 下：

| 入口 | 行为 |
|---|---|
| `/funds/instruments/search` | 认证后检索公共标的，按参数/缓存限频，不能返回他人持仓 |
| `/funds/accounts`、`/funds/accounts/:id` | 本人账户列表、汇总与详情；创建复用个人 accounts 服务的 asset_class |
| `/funds/accounts/:id/positions` | 期初持仓创建，收代码、份额、成本价、生效日和估值口径确认 |
| `/funds/accounts/:id/events` | 空账户或尚无该代码持仓时直接首笔买入，在同一事务建立持仓及事件；重复代码使用既有持仓，不新增第二份 |
| `/funds/positions/:id` | 本人持仓详情与受约束的期初更正 |
| `/funds/positions/:id/events` | 事件列表及有权限的 buy/redeem/cash_dividend/reinvest/settlement 登记，类型使用封闭枚举 |
| `/funds/positions/:id/events/:eventId/undo` | 末笔撤销与重试键、所有日期/归属检查 |
| `/funds/positions/:id/valuations` | 本人净值区间与个人日盈亏历史，缺失项与来源版本明确 |
| `/funds/accounts/:id/refresh` | 本人资源刷新请求，共用按代码限频补齐；只返回本人账户更新情况 |

字段金额/数量/价格为字符串，日期为明确 YYYY-MM-DD；返回 NAV 日期、份额生效日期、当前持仓状态与日盈亏区间，错误区分无匹配标的、无价格、类型不支持、资金权限、归属、封账、重复内容冲突、非末笔撤销。

“我的 → 基金账户”及账户管理的基金详情入口对全部有效登录角色开放；详情采用持仓列表加汇总和数据日期，不为每个金额嵌套多层卡片。操作表单区分期初导入和已完成交易，买卖只选择本人 cash 账户；分红展示现金/再投资方式和实际日期，草稿不受异步行情刷新覆盖。复用现有响应式表单、Money、查询状态与数字组件，不另做无关重设计；360px 移动及桌面均验收。

## Risks / Trade-offs

- [类型和真实币种资料不充分] → 明确保存本人确认的人民币场外单位净值口径，显示代码和源简称；不以价格恒 1、名称关键字或归一化 CNY 做自动分类。类型自动化须在未来有权威契约后扩展。
- [个人交易或分红尚未完整录入] → 基金公开表现不能替代个人表现；首日前一状态缺失则日盈亏为空，相关未确认分红标为待核对。持仓成本价只代表用户提供的期初成本估算。
- [接口限制、晚披露或长时间离线] → 保留有效价格及日期，按代码退避、启动补齐；仅取接口实际覆盖的历史，缺口明确呈现。不能承诺每天固定时刻拿到每只基金当日净值。
- [估值与交易并发、金额尾差] → 数据库幂等键、事件/报价版本、精确十进制与全部赎回尾差清零；资产快照与资金流水分别核对守恒。
- [多日资金过程复杂] → 已完成明细分别保存经济日期和实际资金日期，待结算资金只作受管理事件投影；不扩大为在线订单或自动外部结算流程。
- [用户已有未提交修改] → 实施前读取最新工作区，针对账户和统计接入点小范围合并，保持负债金额、分期、流水筛选、券与普通收支回归。

## Migration Plan

1. 实施时再次核对最新迁移编号；当前最后是 000013，预计新增成对 `000014_personal_fund_accounts.up.sql/.down.sql`，不重写已有迁移。结构升级前按仓库规则备份真实财务数据；本提案阶段不执行迁移。
2. 增加资产子类、基金表及受管理转账关联/唯一约束，旧 asset 回填 cash，旧 liability 保持无基金子类。迁移不得预置任何用户的基金账户、份额或成本，不把测试样例放入 seed。
3. 部署代码时传入服务端 Key 并启用后台检查；无 Key 时旧账本服务仍可运行，基金界面明确未配置。上线及生产部署必须由后续用户请求触发，不包含在本次规划中。
4. 回滚前检查基金账户、持仓、事件和受管理转账；存在个人基金数据时 down SHALL 明确拒绝，不能自动删除或把非零基金账户变成现金账户。纯报价缓存且没有个人基金资源时可安全回退结构。保留数据场景采用兼容版本或明确导出/处理后再回滚，不能只回滚 UI 把基金资产从总资产隐藏。

## Validation Strategy

- 纯计算与服务测试覆盖固定样例、加权追加、部分/全量赎回、买卖费用、现金分红除息、再投资、跨资金日期、建账首日缺口、周末无新价格及报价修订。
- HTTP stub 覆盖成功、HTTP 200 业务失败、429、超时、空值、非法/未来日期、乱序、无类型信息与密钥不进入响应日志；真实只读 smoke 使用环境 Key，保存摘要不保存 Key 或请求头。
- SQLite/服务与 MySQL 集成覆盖四角色、多账号同代码、事件/快照并发、双 worker 同报价、成功响应丢失、封账竞态、失败回滚与填充后 down 拒绝。资金/历史断言至少覆盖多个相邻日期，不能只断言最终金额。
- 前端类型、相关单元测试和隔离 Playwright 覆盖本人多基金、角色门禁、日期与无日盈亏状态、资金账户限制、重复提交/换号、首页与曲线一致、生活预算不变、360px 与桌面截图。现有普通余额、负债、券和统计回归按实际执行列出，不宣称未运行检查通过。
