# Spec Delta

## Purpose

定义四档角色对系统各类资源的操作矩阵，作为 API 鉴权与界面入口显隐的统一依据。

## ADDED Requirements

### Requirement: 设置类操作仅限管理员
账期结算日配置、封账与解封、分类管理、账户管理、预算配置、周期记账模板管理、用户与角色管理 SHALL 仅管理员可操作；其他角色执行时 MUST 返回 403。

#### Scenario: 记账员修改账期设置
- **WHEN** 记账员调用修改结算日的接口
- **THEN** 返回 403，设置不发生变化

#### Scenario: 普通成员修改分类
- **WHEN** 普通成员尝试新增或删除分类
- **THEN** 返回 403

### Requirement: 流水写权限矩阵
管理员与记账员 SHALL 可创建、修改、删除账本内任何流水；普通成员 SHALL 可创建流水且仅能修改与删除创建人为自己的流水；只读成员 MUST 不能创建、修改或删除任何流水。

#### Scenario: 普通成员修改自己的流水
- **WHEN** 普通成员修改创建人为自己的流水
- **THEN** 修改成功

#### Scenario: 普通成员修改他人流水
- **WHEN** 普通成员尝试修改创建人为其他用户的流水
- **THEN** 返回 403，流水保持不变

#### Scenario: 只读成员尝试记账
- **WHEN** 只读成员提交记账请求
- **THEN** 返回 403，且界面不展示记账入口

### Requirement: 查看权限对全员开放
四档角色 SHALL 均可查看全部流水、账户、分类、预算、提醒与统计数据；只读角色与其他角色的区别 MUST 仅体现在写操作上。

#### Scenario: 只读成员查看统计
- **WHEN** 只读成员打开统计页
- **THEN** 看到与其他角色一致的完整数据

### Requirement: API 与界面双重执行
权限 MUST 同时体现在服务端 API 拒绝（403）与前端入口隐藏或禁用两处，界面隐藏 MUST NOT 作为唯一防线。

#### Scenario: 直接调用高权限 API
- **WHEN** 只读成员绕过界面直接调用记账接口
- **THEN** 服务端返回 403，数据不发生变化
