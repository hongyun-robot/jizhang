## Goals / Non-Goals

**Goals:**
- 将公开产品/行情、个人估值资料、个人财务事件划为独立边界，提供同一有效净值序列和历史重放口径。
- 在金融写入事务中保证现金、份额、成本和审计一致；估值派生失败可恢复且不重复资金动作。
- 先验证可部署的匿名采集，再开放产品；把已确认业务范围变成可测试的合同。

**Non-Goals:**
- 不重构全部基金/黄金模块为一个通用投资框架；仅提取确认无行为差异的纯计算或基础设施，避免扩大本变更。
- 不提供银行登录、交易执行或自动推断分红；不实现用户可编辑的公共产品目录或跨账号人工改价。
- 发布遵从用户明确授权，实际发布与例外准入分别留痕；人工补值不作为采样通过证明。

### D1. 独立 wealth 领域与受控产品目录

新增 `asset_class=wealth`，理财 service/repository/handler 独立；账户与产品之间采用一账户多持仓，同一 `account_id + product_id` 一份可累加持仓。公开产品使用稳定内部 ID，唯一外部身份为发行人、登记编码、销售份额代码的组合，记录币种、单位净值估值方式和来源适配器。首批仅 `suyin / Z7003125000238 / J07241 / CNY`；发行人产品代码可保存为核对元数据，不能替代份额标识。

产品目录由版本化迁移/受控发布配置维护，不提供新增任意代码的用户 API。目录有 `pending_validation / enabled / retired` 等准入状态和验收证据版本。只有 enabled 可用于新增期初或首次申购；首次迁移默认 pending_validation，不能仅因迁移完成就视为已接入。已持有产品退出新增目录后，身份与历史继续可读，仍可处理既有持仓赎回、分红、到账和净值补录，且不被自动替换。

选择独立子类而非伪装为 fund，是因为现有身份契约与数据源不同；选择版本化目录而非任意代码检索，是为了落实用户要求的“只能选择已接入产品”。

### D2. 财务模型与跨日事件

2026-10-16 总成本输入补充：已有持仓及其更正采用 total_cost（两位人民币金额）与 shares；事件 Amount 直接保存实际总成本，单位成本除法只派生显示八位小数。旧 cost_price 请求保持原计算语义，二者同时提供时拒绝歧义。参考单位净值独立展示，不进入成本输入；无结构迁移、无旧数据自动重算。

后续用户明确改为净值可填写：opening_nav 默认采用所选生效日精确同日值，缺价留空，允许修改并保存于既有事件元数据；更正回显已存快照，切换日期重新带入，同日手改后刷新保留。该值是建账参考记录，不修改公共或个人净值序列，也不参与成本计算，估值优先规则保持。

新增产品、公开净值/修订、个人补录/修订、持仓、事件、mutation、审计、派生估值及同步槽位记录。金额沿用项目 decimal 与人民币分展示，份额和单位净值最多八位小数；聚合上限沿用现有账户限制，超限拒绝整笔提交。

个人持仓保存 owner/account/product；事件按生效日期和稳定序号重放。期初保存已确认份额与单位成本，推导总成本，允许无行情保存且不补扣现金；无后续依赖时可审计更正。首次申购可原子建立零起点持仓，不要求伪造期初。

- 申购：录入已确认份额、含费实际扣款、费用、实际成交净值、付款日、份额确认日和本人现金来源。费用包含于总投入，不能重复扣款；按实际成交净值核对扣除费用后的本金，不能取当前净值代替。
- 付款日不得晚于份额确认日，二者均为真实且不晚于今天的日期。付款早于确认的历史区间以已投入本金保留待结算资产，费用在份额确认时计为投资损耗；已确认申购仍可补记这段历史；实时未确认申请按 pending-orders.md 单独登记，确认后不再扣款。
- 赎回：按确认份额与真实成交毛额、费用结算净应收，部分赎回比例结转成本，全部赎回清除尾差。已实现盈亏在赎回确认时按确定净额减结转成本核算，待到账期间按净额保留应收，之后到账只重分类资产。
- 赎回到账日期可留空，后来通过引用原事件的 settlement 登记真实到账日期及本人现金账户；不填未来预计到账日。已有到账事实可在首次登记时同事务写入，日期不得早于赎回确认。
- 现金分红：按本人确认的权益、金额和生效日期建立分红收益及应收，不冲减持仓成本；实际到账通过独立 settlement 消除应收并增加现金。红利再投资按实际分红额和确认份额增加成本与份额，无外部现金流水，不重复计收益。

每笔实际资金转移由理财事件生成正金额受管理转账，普通流水不能编辑/删除/退款或伪造关联。关联事件、现金、持仓与 mutation 在现有 `LedgerWrite` 封账互斥下原子提交。相同 owner/request_key/content 只成功一次，内容不一致冲突。补录历史事件须重放所有后继验证无超卖、负成本或已封账事实变化；修正走末笔有效事件撤销后重录，settlement 作为依赖需先撤销。成功财务事务后重建失败仍返回原成功回执并标记待重建。

选择复用基金事件语义而非黄金同日模型，是因为日申周赎会有真实的确认与到账日期差；规则落实在理财模块，不改现有基金计算口径。

### D3. 统一的本人有效净值序列

公共净值主键为 product/date，保留版本；人工主键为 owner/product/date，独立保存当前版本、撤回状态、来源说明及不可变审计，不写公共报价表。

对每个 owner/product，按日期合并：同日有效自动值优先，否则采用未撤回的本人补值，否则该日缺价。估值日使用不晚于当日的最近一条有效单位净值；后补取得的某历史日期真实净值可修订该历史日期起的估值，今天日期的报价绝不倒填更早日期。累计净值仅作披露参考，不参与份额乘价。

人工输入为产品、真实净值日期、有限正数单位净值和来源/更正原因；日期不得未来、早于产品成立或不合法。累计净值不作为首版必填，缺失时显示未知，不推导。仅允许本人已登记的产品（含清仓保留历史）补值。公共同日记录存在时，人工新增、更正及撤回有效记录均拒绝；旧补录转为被自动值取代的只读审计，不因随后某次请求失败重新生效。若未来需要撤销无效公共报价，须另有受控来源修订流程，本版不提供。

人工创建/更正/撤回有 owner 范围幂等键及预期版本，旧版本并发编辑返回冲突；与官方数据写入按统一产品锁协调，同事务重查是否已有自动同日值，避免检查后自动值到齐仍提交有效人工价。全部角色包括只读成员可管理本人补值；仅修改估值资料，不产生任何财务事件。

有效报价身份使用 `{source, record_id, revision}`，个人序列另持有单调的 `effective_series_version`。估值记录当前及前一报价身份、序列版本和事件版本，不能只比较整数 revision。新增/修订/撤回个人日期会改变后继净值区间，因此标记该 owner/product 下全部持仓重建并删除不再属于有效序列的旧快照；自动插入/修订则标记所有相关 owner 重建。即使人工与自动同为 revision=1、数值相同，也更新来源身份与审计。重建成功前读取按同一序列即时计算或明确 pending，不能返回冒充最新的旧快照。

选择 owner/product/date 而非每账户补值，是用户要求本人多个账户共用；选择自动同日优先而非手工覆盖，是为了保留可核对公共事实和跨账号隔离。

### D4. 市值、收益与完整性

理财账户值 = 各产品当前有效份额 × 本人有效单位净值 + 申购待结算本金 + 赎回/现金分红应收；本金、成本、受管理转账与已实现盈亏不再叠加。清仓但仍有应收时账户值为应收额，不能置零。

某持仓非零但无任何截至日有效价时，市值/持仓盈亏/依赖该值的累计盈亏为 null；账户汇总 balance 为 null，另可展示已知小计和待结算金额，总资产标明不完整。零份额不依赖净值，已实现盈亏和应收仍可查看。多产品不同净值日期逐项显示，汇总只给保守截至信息，不能暗示所有产品当天更新。

持仓盈亏为市值减剩余加权成本，已实现为净赎回额减结转成本，累计为持仓盈亏加已实现盈亏加确认分红；费用只通过投入成本/净额体现一次。零成本收益率显示不可算。净值区间盈亏使用当时事件与现金流计算；无新净值不捏造当日收益，缺前一历史基准显示暂无。净值数据本身不足以发现全部分红，页面提示按银行权益核对；用户录入分红后重算相应区间，不宣称仅凭净值已完整识别个人权益。

同一读模型供持仓详情、账户聚合、首页与资产曲线使用。个人补值只失效本人缓存；公共报价变化按持久化持仓 owner 失效相关账号缓存。活动页面每至多一分钟读缓存/聚焦读取后显示新版本，不直接请求银行。

### D5. 匿名浏览器采集与准入验证

2026-10-16 用户明确要求 J07241 提前开放选择，已按 `admission-2026-10-16.md` 留存授权、目录备份及接口验证；随后又要求开启生产自动同步，已完成并真实入库，见 `production-sync-2026-10-16.md`。此例外仅调整该产品的开放顺序；下述采样通过门槛、真实时间证据和通用运维校验不降低；当时 1.4 未完成，现已于 2026-10-20 按 qualification-final-2026-10-20.md 完成真实证据复核。独立采样容器与生产采集服务分开运行。

实施核对（2026-10-16）：通过浏览器自身 UA 取得匹配平台/版本的普通 Chrome 标识，并配置自动化标志后，独立匿名浏览器已能运行官网校验脚本取数。本机、服务器及真实响应 Go 回放均通过；修正重复文字控件定位和异步登记编码等待。完整匿名会话下的无签名 HTTP 查询也已验证，但首版正式采集继续使用浏览器原生请求；不写死 Cookie 或动态签名。细节见 `docs/research/suyin-dynamic-challenge.md`，以下多日准入门槛保持。

基线采用隔离的 Node/Playwright 浏览器采集进程或 Compose 内网 sidecar，负责正常访问苏银官方产品页、运行官网脚本并取得该页面的净值 JSON；Go 适配器只接收结构化结果与来源证据，业务逻辑仍在 Go。采集服务只接受已接入目录产品 ID，页面与目标来源固定白名单，不提供任意 URL/脚本执行接口；内部请求使用部署密钥认证，端口不对公网发布，密钥和会话不下发浏览器或日志。

不复用用户银行登录、不保存人工复制的桌面 Cookie/动态参数、不依赖 Codex 工具。浏览器上下文有超时、串行上限、可回收生命周期；匿名会话失效时至多重建一次，仍失败交由下一检查槽/手动操作，不持续刷新。验证码或登录要求直接记失败，不增加交互依赖。直接 HTTP 仅在将来同样证明可自动恢复时作为优化，不能以复制一次参数替代基线。

产品与份额确认以固定目录映射、官网页身份及请求 fundCode 共同核对；来源内部代码需在采集验证中保存映射证据，不能凭简称、相邻份额或内部代码猜测。仅业务成功且 schema 合法、日期非未来、单位净值正有限、币种/份额映射已确认的记录入库；重复日期不同值必须按确定的来源修订规则处理，歧义批次拒绝并留错误。历史插入不让最新日期倒退；空结果/挑战 HTML/HTTP 200 业务失败不覆盖旧值，不删除此前历史。

上线门槛：目标部署等价环境连续三个自然日的 12 个正常检查槽均无需人工会话操作而得到合法业务响应，至少覆盖一个工作日，且验证启动冷查询、进程重启、匿名会话丢弃恢复和一次真实历史读取。没有新披露可算查询成功，但必须另核对一次新披露或可复现的历史修订处理；取得日期/条数记录和可核对日志。多 worker 重试、超时及限流处理用受控故障测试验证。未满足前目录保持 pending_validation，不允许拿本人补值证明已自动接入，也不以一次桌面成功作为生产验收。

连续三天等具体技术验收参数是本提案选择的实施基线，可在不降低无人值守门槛的前提下加严；不是对苏银披露时间或长期可用性的承诺。

### D6. 每日四槽调度、恢复与刷新

使用 Asia/Shanghai，每个自然日 08/12/18/22 四个槽，周末也可查并保留真实净值日期。每产品/槽持久化完成记录与租约，多进程只能有一个有效执行；网络无法保证绝对 exactly-once，请求失败/租约过期可有限重试，但报价 upsert、财务影响与估值版本必须幂等。

启动时合并截至当前最近一个未完成到期槽，仅补一次历史查询即可覆盖多个漏跑槽，记录被合并槽，不逐槽补发；当天尚无到期槽时恢复最近应执行槽。首次准入采集与手动刷新也经过相同产品租约；未持仓的 enabled 产品无需一直扫全量目录，首次选择前可安排一次冷查询，失败不阻止合法财务保存。停用但有份额/应收/历史待重建的账户继续处理。

手动刷新按产品合并，单产品两次上游尝试间至少 60 秒；同槽自动任务和手动重合可复用本次在途结果。失败退避记录到下次可查时间，常规失败等下一正常槽，不临时增加无界任务；内部一次匿名恢复是单次任务的有限组成。每次尝试区分 `updated / no_new_nav / failed / refreshing`，保存尝试时间、成功时间、净值日期及简短错误。新数据缺少当天净值不算失败，取数时间不能冒充净值日期。

### D7. 独立界面与黄金入口调整

建议路由 `/wealth`、`/wealth/:accountId`、`/wealth-positions/:id`，从“我的”和账户管理进入。列表与详情共享账户、产品选择、期初/申赎/分红/到账、审计、行情历史与本人补录表单；下拉显示发行人、完整产品名、份额代码和币种，不给自由创建未知产品的入口。

净值区明确自动/本人补录、源日期、最近成功检查、错误与重建状态；同日人工值被取代后可查看审计，不能继续覆盖。表单使用项目现有中文日期与响应式选择器，失败/刷新保留草稿，退出换号丢弃缓存和迟到回执。

从 `TxnFormModal.tsx` 删除 `GoldForm` 嵌入、goldMode、专用 footer 条件和模式切换；不能删除普通四类记账仍使用的 Segmented。黄金详情保持 `GoldForm` 与报价刷新；不向弹窗加入理财入口。同步更新 `gold-accounts` 和 `home-dashboard` 的旧规范，避免“代码删除入口但主规范仍强制提供”的冲突。`gold.mjs` 转从黄金详情发起买入，保留响应丢失重试、草稿与只扣一次的断言。

### D8. 权限、生命周期和封账

全部角色能维护本人账户、合法期初和人工净值、查看行情及审计；申赎/分红/再投/到账/交易撤销遵循已有资金权限与创建人约束。owner 来源只信认证身份；后台依持久化 owner 重估，公开行情共享不共享人工资料或持仓。理财账户不能被普通支付/收支/退款/还款/周期模板/券/其他投资交易当作现金来源，服务端与选择器双重校验。

有期初、有效/已撤销事件、应收或持仓审计的账户禁止删除/改类；停用保留估值、应收和历史，可记录既有持仓处置/权益/到账，禁止新期初和申购；排序和改名不改变财务数据。

理财财务修改校验本次实际改变的全部生效/权益/资金日期及受影响后继成本日期，任一封账则原子拒绝。旧期赎回或分红仅作为新期到账的只读来源时，不把原确认日视作本次修改日期；新期合法到账只结算应收，不能重写已封账确认事实。人工净值按已确认决策属于估值资料，与公开净值修订一样可重算已封账市场价值，但必须保留来源和审计，不能改现金、已实现成本/收益、份额、分红事实或封账收支合计。

## Risks / Trade-offs

- [匿名浏览器在目标环境仍被网站校验拒绝] → 将采集准入验证放在 UI 全量实现前，产品保持待验证；不承诺通过，不借人工补录绕过验收。
- [浏览器服务增加内存及部署依赖] → 内网隔离、串行上下文复用、超时回收、独立健康检查和资源限制；不把浏览器塞进现有 Go 请求事务。
- [手工补值错误影响本人所有账户及历史] → 明确作用范围、强制来源/更正说明、版本冲突、撤回与审计；公共自动值优先，不影响他人。
- [行情身份切换或删除日期导致历史快照残留] → 记录完整来源身份和序列版本，重建全部受影响本人仓位并清理失效日期，测试同 revision 切换及前一报价边界。
- [跨日或费用被重复计资产] → 同一事件重放及结算引用，含费投入/净到账只记一次，现金转账不作为投资资产额再次聚合。
- [现有多投资模块复制逻辑] → 首版保持领域清晰，仅有限复用稳定纯计算，新增回归保护已有基金和黄金；后续公共抽象另行设计。

## Migration Plan

1. 实施时按当时最高编号新增成对迁移：产品/行情/补录/事件/审计/同步状态及理财受管理转账关联。只种产品元数据且默认待验证，不创建个人账户或资产；升级前备份，验证旧现金、负债、基金和黄金金额不变。
2. 先部署等价测试环境的匿名采集服务和受控适配器，执行 D5 验收；满足后通过受控配置/迁移标记对应版本 enabled，再完成全功能验收。此步骤不授权本次提案阶段实施或生产部署。
3. 前后端同步发布 wealth 类型与 null 余额支持，再开放产品选择；新数据库字段和接口保持向前兼容，黄金快捷入口移除与独立入口回归一并发布。
4. 回退时优先关闭新产品准入/新增资金写入、停采集并保留只读历史和已保存数据；已有非零持仓或未知余额时不能直接回退到不识别 wealth 的旧客户端/聚合版本。空库或无理财财务/人工审计引用时才允许 down；有历史则 down 明确拒绝，采用保数据的前向修复。
5. 更新 README 的本地依赖、采集配置、净值说明、独立入口与回滚限制；实施阶段保存采集证据、测试结果和桌面/移动截图，不将财务数据或会话凭据写入共享日志。
