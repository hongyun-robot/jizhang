## Why

“我的”已提供个人账户与分类管理，平台 / 商家却仍是全员共享目录且只能在业务表单中新增。用户需要像分类一样独立维护自己的平台 / 商家，避免自己的新增、修改或清理影响其他账号。

## What Changes

- **BREAKING**：平台 / 商家从账本共享目录改为个人目录，读取、新增、重命名和删除均限定当前登录账号；管理员也不能管理他人的目录。所有有效登录角色包含只读成员均可维护本人目录，资金写权限保持既有规则。
- 在“我的 → 我的记账选项”增加“平台 / 商家管理”，提供本人名称列表、搜索、新增、重命名和确认删除，桌面与手机可用，路由归属于“我的”。
- 购券、编辑券、手工记账、编辑流水及固定分期新消费统一使用本人目录，保留字段内明确创建、可选字符串、失败降级及草稿保护；随业务保存的新名称与业务事务同时成功或回滚。
- 升级为现有账号生成迁移前共享目录的独立副本，补入本人历史记录中缺少的名称；新账号按稳定数据库模板初始化默认名称。个人默认目录只初始化一次，删除后不因刷新或重启恢复。
- 管理页重命名仅改变个人候选名称，历史券与流水的名称文本保持；删除仍被本人保留记录使用的名称返回冲突。不会按相同名字合并不同账号的目录或改写财务历史。

## Capabilities

### New Capabilities

无；扩展现有平台 / 商家能力。

### Modified Capabilities

- `voucher-platform-options`：个人目录、账号内名称去重、管理页维护、默认初始化与升级兼容，替换现有共享语义。
- `ui-shell`：增加“我的”个人平台 / 商家管理入口及路由，覆盖新页错误态和个人目录异步回填保护。
- `identity/access-control`：平台 / 商家目录采用与个人分类一致的全角色本人管理权限，API 与界面同时执行归属限制。
- `vouchers`：券使用本人平台 / 商家目录，继续使用字符串接口及既有券权限和封账规则。

## Impact

- 后端：`VoucherPlatform` 模型与仓储、目录服务与券处理器、目录路由、券创建 / 重试 / 修改和流水创建 / 修改中的目录写入，以及数据库模板和账号一次初始化。使用认证身份确定归属，不接受客户端指定 owner。
- 数据库：新增成对迁移（当前最高编号 000014，实施时采用下一空闲编号），增加目录归属、账号内精确名称唯一约束、默认模板与初始化标记，保存升级前目录快照并定义受保护回滚；不改变财务表的记录、金额或日期。
- API：保留 `/api/v1/voucher-platforms` 的 GET / POST 及返回的 `id` / `name` 结构，改为本人范围；新增 PUT / DELETE `/api/v1/voucher-platforms/:id`。业务 `platform` 字符串接口保持兼容，旧客户端将观察到个人目录语义。
- 前端：`Mine.tsx`、`App.tsx`、`navigation/routes.ts`、新管理页、目录 mutation 与缓存、`PlatformInput` 会话和草稿保护；沿用现有界面组件和主题，不新增外部依赖。
- 验证与文档：更新现有共享目录断言，覆盖四角色管理、跨账号拒绝、初始化、升级与回滚、并发去重、事务回滚、切换账号迟到响应，以及桌面 / 手机管理和业务表单回归；更新 README 中的共享目录说明。
