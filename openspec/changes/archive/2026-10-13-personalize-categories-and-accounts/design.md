## Context

动机与行为范围见 `proposal.md`。用户已确认：全部登录角色可创建并管理本人分类与资金账户，分类 / 账户按登录账号独立，平台 / 商家保持共享。

现有 `accounts.owner_id` 仅隔离个人负债；`account_ownership.go` 放行全部资产并以 `CanManageSettings` 限制资产管理。分类没有归属，路由写操作限定管理员。`App.tsx` 和 `navigation/routes.ts` 都限制 /accounts、/categories，`Mine.tsx` 把入口放在管理员分组。`Accounts.tsx` 已具备资产 / 负债创建表单，个人负债另有 `PersonalLiabilityAccountModal`。

`ResponsiveSelect` 当前只选已有项，手机复用 `SelectionSheet`；`PlatformInput` 已实现明确创建、草稿保留和迟到响应保护，可复用交互原则。平台目录本身是全账本共享的字符串目录，不是资金账户。

流水已有个人负债筛选，但资产默认可见。统计缓存已有账号维度，收支聚合仓储仍使用全账本 SQL；预算服务未接收登录身份且按全部分类构造进度。券和周期任务通过负债归属检查间接授权，需要同步扩展。迁移 `000011` 已确立个人负债归属，不能推翻已有负债身份或复制其财务历史。

## Goals / Non-Goals

**Goals:**

- 将账号身份贯穿目录、资源引用、查询、后台生成与缓存，归属在服务层执行，数据库限定查询范围。
- 在保留真实资金与历史关联的前提下完成共享目录个人化；为遗留混合归属提供有界的只读兼容。
- 通过一个可复用账户创建入口完成管理页和字段内创建，保留资产 / 负债业务校验、移动层级与父草稿。

**Non-Goals:**

- 不修改共享平台 / 商家目录及消费信用类型目录，不新增跨账号转账或家庭共享账户模式。
- 不扩大只读角色的资金写权限或非管理员的预算、账期、用户管理权限。
- 不按资金账户名称合并实体，不把期初余额当流水补记，不重新分配既有负债。

## Decisions

### 1. 所有实例资源统一归属，角色与归属分别校验

资产与负债均以服务端当前用户的 ID 写入 `accounts.owner_id`；分类增加 `owner_id`，父子必须同属一人。请求不能指定或变更归属。账户改类型仍保留归属，并执行历史、零余额与账单规则限制。个人目录读写只要求有效登录与本人归属，使用独立权限函数，不能把 `CanManageSettings` 改为全员放行。

分类服务新增带 actor 的读取和写入接口，处理器把当前用户传入；账户服务的 CreateFor / UpdateFor / DeleteFor 去掉资产的管理员限定，统一校验本人。仓储采用显式 owner 参数及 owner 索引，不把用户身份藏在全局变量或连接状态中。身份未知的 HTTP 路径不能降级为无归属读取。全部引用入口，包括分类父节点、转账另一端、退款原流水、分期费用账户和周期模板，都必须检查资源归属。

替代方案是只去掉界面和路由的管理员门禁；它既不满足个人目录，也会向成员开放旧共享资产的管理，故不采用。

### 2. 数据库模板与一次初始化

迁移初始化默认资产模板和独立的两级分类模板；负债继续使用 `liability_account_types` 的数据库模板。模板与用户实例分表，不能把管理员当前个人分类作为以后新用户的默认模板。用户增加资产和分类初始化标记，保留已有 `liability_accounts_initialized` 语义。个人首次初始化在事务中锁定用户行，创建实例和完成标记原子提交，失败可重试，成功后不再补种；服务启动不插入个人默认记录。

升级为既有用户复制迁移前分类树的独立副本，保留原排序及自定义名称；迁移后的新用户按稳定模板初始化。父子先按模板 / 来源 ID 映射，不按名称匹配。原有默认资金已经归属的账号复用原账户，额外实例仅零余额。既有已初始化个人负债不因本次资产 / 分类初始化恢复已删除默认负债。

替代方案是在每次读取时按缺少的名称重新补齐；它会恢复用户删除的数据，也无法区分同名独立账户，故不采用。

### 3. 保守迁移资产与分类，保留资金链

迁移前生成归属及对账报告。资金账户原 ID、期初余额、所有流水金额 / 日期 / 创建人 / 请求标识 / 关联链保持。确定旧共享资产归属时，将转账、关联退款、券支付及分期费用 / 结清来源纳入资金链，互相连通的旧资产作为整体处理：只有一个既有个人负债归属锚点且历史使用一致时归该人；无锚点且全部历史使用者唯一时归该人；有多个归属锚点、多个使用者或无人使用时归初始管理员（最小管理员 ID，无管理员时最小用户 ID）。所有已有负债归属保持。归属报告列出规则、涉及旧账户、混合链和暂停资源，不能猜测按各创建人的消费额分割资金。

原分类 ID 由初始管理员保留，其他账号复制整棵旧树，持久化 `(owner_id, source_category_id) -> category_id` 映射，逐级重建父节点。流水按主要资金账户归属映射；券及券事件按原支付账户归属映射；负债本金 / 手续费分类配置按其负债归属映射；周期模板按创建人映射。旧分类预算保持原管理员分类引用，不把预算金额复制到其他同名副本。逐个覆盖持久化分类引用，校验引用完整性和已保存请求幂等信息，不因 ID 映射重新生成任何资金事件。

旧资产与个人负债可能仍存在跨账号历史还款 / 费用关联：保留原引用，以只读历史说明展示本人账户受影响金额；对方账户展示固定的历史关联说明，不能跳转详情或枚举对方分类。余额计算读取作用于本账户的全部原资金净额；用户面向的消费按实际支付账户归属计一次。历史资金修正必须拥有所有受影响资源，否则拒绝。迁移失配的周期模板暂停；未发生的负债费用计划或其他自动配置存在外部账户引用时进入可解释阻塞状态，待本人选择合法来源后继续，不能偷偷改用零余额新账户。

替代方案为每人复制带余额的旧资产，或按创建人切分流水；前者复制资金，后者破坏转账、余额与组合操作关联，故不采用。

### 4. 查询范围统一，避免聚合绕过隔离

复用账户归属策略形成资源过滤，扩展 transaction 列表 / 总数 / CSV / 关联退款，券列表 / 详情 / 汇总，周期模板与负债各操作。历史跨账号资金事件仅按前述只读例外返回，正常的新事件全部资源同属本人。个人统计 SQL、分类映射、资产曲线和首页采用同一 owner；资产余额不按 `created_by` 过滤，避免迁移后丢掉旧资金。Redis 统计继续使用用户维度，写成功使相关数据失效；退出 / 换号沿用会话 epoch 隔离，迟到响应只能更新原 scope。

预算保持账本总预算金额，个人页面明确标注“本人进度”，消费按本人支付资源计算；分类预算按 owner + 一级分类 ID 展示，非本人条目不能返回。管理员保存本人的分类项只替换该范围，不能用现有整单缺项删除方式清除其他管理员目录条目。预算提醒增加 owner 去重范围；历史全账本预算提醒保留在初始管理员历史，不转发给全员。封账与审计仍按原账本全局范围执行，与个人统计分别提供查询和缓存。

替代方案仅隔离账户列表、保留全账本统计和券汇总；它会通过金额、分类排行、未用券或后台提醒继续暴露他人资源，故不采用。

### 5. 账户字段使用独立创建组件

从 `Accounts.tsx` 提取可复用账户编辑 / 创建表单，个人负债入口共享必要的类型目录与账单校验。增加账户专用选择组件，内部复用 `ResponsiveSelect` / `SelectionSheet` 的基础交互，并显式接受允许类型、禁用、选项过滤、同账户排除和 onCreated 回调。不把所有 `ResponsiveSelect` 变为可创建，避免角色、状态、筛选和分类产生无关创建入口。

记账账户、转账两端、购券支付账户、周期模板账户、还款资金、分期与结清费用账户接入；仅资产字段固定创建资产，历史锁定字段关闭创建。选项提供“新建账户”，不存在的有效搜索名可预填“创建「名称」”；新建默认为零余额资产，用户可在允许类型内选择个人负债并填写必要规则。账户始终使用数字 ID，不采用商家文本“使用此名称”的降级路径。账户可有同名独立实体，界面应结合类型 / 可辨识标识区分，明确创建和请求幂等替代名称去重。

新建表单与父表单不导航离开。手机选择层打开先聚焦非输入元素，进入新建也不自动聚焦名称；选项层在打开创建层时暂时退出焦点捕获，取消创建后恢复该层，成功后关闭两层并回到字段。键盘、遮罩、Escape 及滚动锁只操作当前层。创建期间禁止重复请求和父资金提交；以会话 epoch、父编辑对象、字段版本守卫回填，取消 / 换对象 / 选其他账户即使请求最终成功也不改新草稿。

替代方案是在搜索框内直接按名称 POST 一个默认账户；它无法表达负债配置、合法期初余额和字段类型限制，故使用完整创建表单。

### 6. 创建请求幂等，与名称分离

账户创建 API 增加可选 `request_key`，新客户端每次明确的新建意图生成 UUID，未确认结果的重试保留原 key 和资料。新增持久化创建请求记录，唯一键为 `(owner_id, request_key)`，保存规范化负载哈希及账户 ID；创建请求记录、账户和账单配置在同一事务内提交。同 key 同内容返回原账户，同 key 不同内容返回 409；并发命中通过唯一约束及当前已提交读获得相同结果。已有无 key 客户端可继续创建合法本人账户，新内联入口必须发 key。

账户删除后保留创建请求墓碑；旧 key 重放返回已删除冲突，不能重新建户。首次校验失败不登记成功请求；超时未确认时先使用原 key 核对结果，不能更改资料后悄悄复用或生成另一个请求造成重复期初金额。名称独立校验并 trim 至 1–64 Unicode 字符，不建立 owner + name 唯一约束。

## Risks / Trade-offs

- [多人旧资产无法还原真实所有者] → 采用确定的整体归属规则和报告，不拆钱；迁移后的非所属账号不再看到原共享资产。
- [旧组合操作涉及不同已有个人负债] → 保留原资金链与本人必要历史，只读兼容；新增和修正不绕过归属，失配自动配置暂停或阻塞并说明修复条件。
- [分类 ID 映射遗漏业务表] → 逐表覆盖流水、券、事件、模板、预算、分期 / 结清配置，验证父子关系、外键、请求重试以及金额守恒。
- [预算进度从家庭消耗变为本人消耗] → 保留总预算配置，明确本人进度文案，不按同名分类分享预算；封账审计仍全账本。
- [手机嵌套层级抢焦点或键盘遮挡] → 共用现有浮层和可视区域设施，创建层接管焦点，验证取消恢复、断点切换和父层销毁。
- [回滚把私人目录重新公开] → down 在未发生个人修改 / 新财务引用时才允许精确撤销；启用后继续写入的数据不能自动无损合并，应通过备份恢复或专门数据迁移回退。

## Migration Plan

1. 实现与验证均先在独立测试库进行。对生产迁移另行安排备份与写入暂停；本提案不执行部署。
2. 新增成对迁移（当前最高编号 000011，实施时取下一空闲编号）：分类归属 / 索引、默认模板、一次初始化标记、创建请求记录、旧资产归属及分类映射。
3. 写入暂停下生成迁移前报告及逐账户余额、财务表 ID / 金额 / 日期 / 创建人 / 关联基线，冻结旧分类快照；迁移中整体处理原资产归属并建立各账号分类副本、零余额默认资产、分类引用映射和阻塞资源。
4. 校验全部原账户余额、负债归属、流水资金合计、券份额成本及关联记录不变，校验所有新实例归属与 parent 映射；检查多账号同名、管理员越权和初始化重跑。
5. 同步切换后端和前端，清理旧统计缓存，验证各账号目录、历史说明、后台任务及桌面 / 手机创建流程后恢复写入。
6. down 必须先验证迁移后实例与引用未改变；符合条件时按映射恢复原分类引用和原资产共享状态，不删除既有负债或财务历史。不满足条件则明确拒绝 destructive down，使用备份与独立对账迁移处理，不能以回滚为由删除新流水或合并不同人的期初余额。
