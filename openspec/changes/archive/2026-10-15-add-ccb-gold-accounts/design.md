## Context

动机、用户确认的范围及排除项见 `proposal.md`。本次只生成规划，不修改业务实现。

已核对的现状：

- `backend/internal/model/account.go` 以 `asset_class=cash|fund` 区分资产，账户余额为非持久化聚合字段。`account_repo.go` 对基金以估值覆盖流水净额；`stats_service.go` 的资产曲线已有未知值和基金估值回调。
- 基金已有按事件重放的成本、真实现金转账、末笔撤销、幂等与 `repository.LedgerWrite` 封账串行保护。`FundNAV` 和估值按日期唯一，不能直接保存黄金双边盘中观察；基金期初缺净值必须拒绝，黄金已确认允许无报价保存，二者不能混用入口契约。
- `frontend/src/components/TxnFormModal.tsx` 当前有收入、支出、转账、退款和购券入口；黄金需要专用模式。`frontend/src/domain/accounts.ts` 等部分现金选择器仅排除基金，新增黄金后必须改为明确允许的现金/负债类型。
- `frontend/src/api/cache.ts` 已集中管理登录会话范围的业务失效；黄金报价变化还需使首页、账户、资产曲线和受影响用户的服务端统计缓存失效。
- 建行取数证据见 `docs/research/ccb-gold-accumulation-api.md`：同一匿名 Cookie 会话先访问 `TXCODE=100119`，再请求 `NGJS01`，得到 `Cst_Buy_Prc`、`Cst_Sell_Prc`、`Tms`。响应可能是标记为 HTML 的 JSON；未找到该网页内部接口的正式开放 API 契约。
- 工作区已有独立的负债改动，实施时须保留。新增迁移号需以实施时目录实际最大值为准，不能复用现有或其他变更占用的编号。

## Goals / Non-Goals

**Goals:** 建立黄金财务事件与公共报价两个边界，准确连接持仓、现金、实时参考值和可追溯日终资产；允许行情失败时独立记账；使重复请求、异步估值失败、封账竞争和换号均不破坏资金。

**Non-Goals:** 不抽象统一所有投资产品的万能引擎，不修改基金的 `.OF` 识别及净值更新时段；不获取个人银行资产、不执行建行真实交易；不把当前双边价接口当成可靠历史价格 API。

## Decisions

### 1. 独立黄金资产与固定产品键

增加 `asset_class=gold`，黄金账户普通 `opening_balance=0`，固定产品键建议 `ccb:personal-gold-accumulation:CNY`。一账户一个黄金持仓，同一用户可以多个账户；账户目录排序沿用现有完整目录。

新增 `internal/ccb` HTTP 适配器、黄金领域计算文件和独立 `GoldService`/repository/handler；与基金共用账户、现金转账及写账锁的既有基础设施，避免把黄金编码成基金标的或对所有金融产品做大范围重构。纯计算不执行 HTTP 或资金写入，service 负责业务事务，repository 负责查询和持久化。

未选择复用 `FundPosition/FundNAV`：它们的场外身份、日净值、分红与待结算语义和黄金范围不一致；直接复用容易继承错误的无报价拒绝规则或历史回填规则。

### 2. 事件模型和确定的金额语义

建议新增以下表，最终命名可沿仓库命名惯例调整，但约束不能省略：

| 资源 | 核心字段及约束 |
|---|---|
| `gold_positions` | 唯一 `account_id`、`owner_id`、固定产品键、事件版本、重建标记；当前克数/成本由有效事件重放 |
| `gold_events` | `opening|buy|sell`、克数、实际总成本或净到账、可空费用、交易日期、现金账户、创建人、撤销时间；事件留痕 |
| `gold_mutations` | `(owner_id,request_key)` 唯一、动作/目标/规范化内容哈希、事件回执；覆盖期初、更正、买卖和撤销 |
| `gold_audits` | 操作人、动作、关联资源、前后快照与时间，保留合法期初更正和撤销 |
| `gold_quote_observations` | 产品键、买入价、赎回价、银行 `quote_at`、系统 `fetched_at`、成功尝试标识、修订关系；成功观察追加保存 |
| `gold_quote_syncs` | 产品唯一、当前有效观察、最近尝试/成功、小时槽、租约令牌/到期、错误/失败次数、手动冷却到期 |
| `gold_valuations` | 每账户/日期唯一、克数/成本/已实现、可空市值/盈亏、事件版本、观察 ID、状态；可重建派生值 |

`transactions` 增加唯一可空 `gold_event_id`，与基金/券等受管理关联互斥；用途增加黄金买入和黄金卖出。转账金额永远是实际现金，不将黄金克数当人民币金额。

金额全部以十进制字符串跨 API，后端使用精确 decimal。现金总额与费用最多两位小数；克数和输入每克成本最多八位，拒绝九位小数、指数/非有限数、非法日期、负数及越界乘积，沿用现有金额上限。内部成本结转保留至少十六位小数，展示金额最终四舍五入至分。期初每克成本模式先计算并显示待确认的分级总成本，保存该总成本及原输入模式到审计；平均成本是派生值，不能双字段各自编辑后不一致。

费用可空以区分“没有单列费用”和“已确认费用为零”。买入总扣款 `A` 包含费用 `F`，本金 `A-F`，平均每克成本 `A/g`，有费用明细时另展示实际不含费单价 `(A-F)/g`。卖出输入净到账 `N`，有费用时毛成交额 `N+F`，实际成交单价 `(N+F)/g`，净每克回款 `N/g`；费用不从净额再减一次。

### 3. 重放、补录和资金写入

有效事件按北京时间交易日期、稳定 ID 顺序重放：

- 期初 `g>0`、总成本 `C>=0`，不生成现金或日常收支；每个账户只能有一个当前有效期初，并且只能位于其交易起点之前。直接首笔买入无需期初。
- 买入：`G'=G+g`，`C'=C+A`；现金来源减少 `A`，只接受本人可用现金资产。
- 部分卖出：`K=C*g/G`，`G'=G-g`，`C'=C-K`，`R'=R+N-K`；全部卖出取完整剩余 `C` 并清零。收款现金增加 `N`。
- 市值 `M=G*sell_price`，持仓盈亏 `U=M-C`，累计 `P=U+R`。`G=0` 时 `M=U=0` 且不需报价；非零克数无价时 `M/U/P=null`，成本与已实现 `R` 已知。成本为零时收益率为空。

所有财务操作使用账号范围幂等标识，锁定黄金账户及受影响现金资源，在 `LedgerWrite` 同一事务中检查归属、角色、创建人、状态、全部受影响账期，写事件、黄金受管理转账、版本和审计。金融事务不等待上游行情，允许无报价保存。任何一步失败都完整回滚；相同内容的成功重试直接返回原回执。

允许补录开放历史日期，但必须从插入点重放全部后继事件，检查每一步无负克数和合法成本，并拒绝改变已封账后继的克数、成本或已实现结果。首版一个交易日期即持仓与资金日期，不提供分开的跨日字段；若请求携带跨日语义明确拒绝。

末笔定义为按有效日期、ID 排序最后的有效事件，不是最近创建的一行。修正买卖只能先撤销末笔再重录；期初直接更正只限无后续有效交易且全部受影响日期开放。撤销以撤销标记和审计保留原事件，同时移除对应转账的有效现金影响，不能经普通流水改删绕过。引用过的停用现金账户可按既有历史权限恢复原事件的资金影响，不能改为新账户掩盖历史。

财务事务同时持久化 `rebuild_pending`/事件版本。事务成功后派生重建失败不改变原回执；后台和估值读取重试重建，旧版本必须显式标记待重建，不能当作最新历史返回。不把行情写入与个人扣款放在同一个外部网络事务里。

### 4. 建行适配器和匿名会话边界

固定 HTTPS 基址 `https://www2.ccb.com` 与官网已观察路径，只允许同一可信主机重定向；不接受用户自定义上游 URL。适配器持有内存 Cookie jar：

1. 首次访问 `/tran/WCCMainPlatV5?CCB_IBSVersion=V5&SERVLET_NAME=WCCMainPlatV5&TXCODE=100119` 初始化匿名会话。
2. 同会话 GET `TXCODE=NGJS01`，按有界响应内容解析 JSON，不仅依据 `Content-Type`。业务必须 `SUCCESS="true"` 且 `retCode="000000"`。
3. 检查 `PM_Txn_Vrty_Cd="33"`、`CcyCd="156"`，十进制解析两个正价，上海时区解析 `Tms`（可带毫秒）；未来容差最多五分钟。产品识别基于已实测配置，不从简称或价格大小猜测。
4. 明确识别会话提示时丢弃旧 jar，重建后最多重试一次。其他网络、限流、坏数据失败直接记录，等待下次小时任务或用户手动请求，不高频循环。

使用 15 秒总请求超时、4 MiB 响应上限及可注入 transport/clock 做离线验证。Cookie、原始会话 HTML、完整请求头不返回前端或日志。适配器只发送公开产品查询参数，不向银行发送用户克数、成本、账户或交易数据。不回退到 XML 定期价、期货价或第三方账户黄金价。

报价源时间晚于当前有效报价时才推进当前价；同源时间同数值保存新的成功观察但不制造新行情，仍更新 `last_success_at`。同源时间不同数值追加修订并保留原观察；旧源时间倒退视为数据异常，不覆盖较新价。所有观察不可变，历史曲线引用当时观察，不被今天修订静默替换。

### 5. 小时调度、共享缓存和手动刷新

公共缓存按产品键唯一，MySQL 为持久化事实来源，可用已有 Redis 做短读缓存；不能只依赖进程内缓存。读取返回当前有效观察、源时间、成功获取时间和最近错误，不根据 TTL 删除最后有效价。

后台北京时间每小时整点执行一次（`0 * * * *`），全天包含周末，适用于仍有黄金账户的产品，停用但有持仓也必须纳入。第一个黄金账户建立时可安排一次合并冷查询，账户和事件保存不等待该结果。启动恢复仅检查当前尚未尝试的小时槽，失败槽不在同一小时紧密重试，不补打离线期间每个小时。

数据库持久化小时尝试槽及产品租约；建议租约 60 秒并使用令牌围栏，过期持有者不能写回新 owner 的状态。多 worker 对同一自动槽最多一个实际请求。未完成查询与手动请求可等待同一结果；锁竞争失败返回缓存和进行中状态，不再重复发起请求。

买入/卖出页面手动 POST 刷新可越过一小时普通缓存。全产品设置 30 秒最小尝试间隔并合并正在运行的请求；冷却内响应包含已有报价、进行中/冷却状态和下次可刷新时间，不宣称重新查询成功。该冷却是保护官网的实现选择，不是建行公布的限频。手动尝试不移动固定小时计划；小时与手动同时到达合并为一次查询并满足该小时槽。

分别维护 `quote_at`、`fetched_at/last_success_at`、`last_attempt_at` 及最后错误。错误即刻提示；从最后成功获取起满两小时显示 `update_error`，从未成功则按首次尝试起点计算，持仓仍为 `no_price`，报价查询状态可显示 `update_error`。合法但源时间未推进是 `source_unchanged` 信息，不是查询失败；成功重复观察会清除连续查询失败告警，但不会更改源时间。

GET 页面读取和前端一分钟刷新只读缓存，不发建行请求。新观察只重建需要变化的估值并失效对应服务端统计；后台不借触发者身份执行个人资金写入。前端在活动页面一分钟内重新读取或聚焦读取，实现详情、账户、首页与曲线一致。

### 6. 当前估值和历史观察的区分

当前余额采用最新有效缓存，即使源报价在上一交易日也可作带时间和状态的参考值；不因周末强制资产清零。报价不存在时 `balance/market_value=null`，增加或复用 `valuation_status`、`complete`、`quote_at`、`fetched_at`，现金/负债已知余额仍按原规则返回。前端 `Account.balance` 扩展为空值联合类型，全面检查求和、Money、排序、选择器标签及图表，禁止 `Number(null)` 被误当真实零。

历史曲线使用有效事件截至日终的持仓。对已结束日期 `D`，选择系统于 `D` 成功保存、且 `quote_at` 不晚于 `D` 日终的最后报价观察。银行源时间可能较早，必须保留其真实时间；这表达当日实际看到的参考价，不声称当日有银行新报价。没有当日有效观察且持仓非零则该账户和总资产点为空，已知其他账户仍可展开。建账前及清仓后为零。当前日允许最新缓存，与相同事件/观察版本的账户余额保持一致；日终落为历史时按上述已保存观察决定完整性。

以 `fetched_at` 为观察事实可以区分“当天成功查到银行旧报价”与“当天没取到任何报价”。未选择直接将最近一条价格无限前填所有历史日：用户已确认历史缺价要保留缺口。未选择今天查询的源日期去回填过去：取得报价的时间不等于当时系统已知时间。

### 7. API 和表单的职责

账户创建和排序仍走现有 `/accounts`，类型限制由后端校验；黄金相关建议 `/api/v1/gold` 下提供：

| 方法与相对路径 | 用途 |
|---|---|
| `GET /quote` | 认证后读公开报价缓存及查询状态，不访问建行 |
| `POST /quote/refresh` | 有效登录者明确刷新固定建行产品，合并与冷却；不含个人持仓数据 |
| `GET /accounts`、`GET /accounts/:id` | 本人黄金账户、持仓及盈亏汇总 |
| `POST /accounts/:id/opening`、`PUT /accounts/:id/opening` | 幂等期初录入及合法更正 |
| `POST /accounts/:id/events` | `buy|sell` 同日真实财务操作，空账户可首笔买入 |
| `GET /accounts/:id/events`、`GET /accounts/:id/valuations`、`GET /accounts/:id/audits` | 本人历史及估值版本 |
| `POST /accounts/:id/events/:eventId/undo` | 幂等末笔撤销 |

事件写接口接受字符串 `grams`、`cash_amount`、可空 `fee`、`trade_date`、`cash_account_id`、`request_key` 和备注；期初以显式 `cost_mode=total|unit` 加对应值表达，规范化为同一总成本口径后幂等比较。响应带当前事件版本和必要回执，不让缓存估值失败掩盖已完成交易。HTTP 错误区分 403 权限、409 依赖/冲突、400 输入（沿用仓库错误响应）、行情刷新失败/冷却状态，不以 HTTP 200 当业务成功。

前端增加黄金 API、纯输入/金额解释逻辑、列表/账户详情及共用黄金交易表单；`TxnFormModal` 的模式与普通 `TxnKind` 分离，不把 `gold_buy` 当通用 `/transactions` 类型提交。保留现有四种普通记账、购券、草稿和提交防重语义；黄金模式直接在同一 Modal 内显示表单，账户详情复用该表单而不是复制逻辑。切换普通/黄金模式保存各自会话内草稿，退出账户会话统一清理。

报价区同时显示买入/赎回价、源时间、成功查询时间和手动刷新；金融金额只由用户录入真实成交，刷新永远不重填金额。页面明确“登记已完成交易”，避免按钮被理解为向银行下单。空黄金账户卖出禁用，空目录引导通过有类型限制的账户创建建立黄金账户；现金来源字段仅能新建现金资产。金额、克数、费用和日期输入沿用触屏字号、中文日期及错误保留规则。

新增 `gold` 缓存失效组，涵盖黄金、账户、统计、流水与通知；账户增删启停也失效黄金入口，封账状态改变失效黄金可操作状态。所有个人 query key 使用既有登录 scope，报价可共享数据但 UI 迟到回执仍须会话 gate。后端原有 `IsCash` 语义可复用，前端全部 `asset_class !== 'fund'` 现金判断需审计，基金、券、周期、还款等不能误选黄金。

### 8. 权限、封账与对账约束

沿现有本人资源模型：viewer 可管理本人账户、合法期初和查询行情，不能买卖/撤销资金；其他角色按原创建人资格操作。所有黄金路由按资源归属校验，原始事件 ID 不能越过账户归属。末笔撤销、历史补录和期初更正检查所有受影响日期及后继财务状态；报价市场估值可更新，但不得改封账收支审计或成交记录。

普通交易编辑、删除、退款、专用撤销入口均需识别 `gold_event_id` 并拒绝分离资金与克数；不能只隐藏前端按钮。流水、最近记录与 CSV 显示黄金专用用途、产品和账户及详情导航，保持既有正金额转账和导出符号约定，消费影响零。

## Risks / Trade-offs

- [官网内部接口缺少对外稳定契约] → 隔离适配器、离线响应夹具、匿名会话有限恢复、持久化最后有效报价及手动重试；不承诺官网 SLA，也不以其他市场价静默降级。
- [小时更新具有延迟且银行源时间可能不推进] → UI 始终展示源时间与获取时间，买卖表单提供明确刷新；记录真实成交而非按参考价自动扣账。
- [缺报价仍可记账导致总资产未知] → 这是用户确认的可用性选择，返回空值及完整性状态，覆盖全部资产消费者；不以零、成本或现金净额粉饰已知总额。
- [历史报价观察不足] → 不接入未经核验的历史接口，保留曲线缺口并解释；初次接入不会补造过去市场价值。
- [重复/并发/补录造成成本漂移] → decimal 事件重放、账号幂等、账户锁、尾差清零、后继验证和封账串行测试。
- [共享刷新放大上游请求或跨号污染] → 产品级租约、30 秒冷却、无自动快速重试，报价共享但持仓、权限与客户端 scope 隔离。
- [异步估值失败或旧租约迟到写回] → 事件版本/待重建持久化、报价观察不可变、租约令牌围栏及投影一致性校验。

## Migration Plan

1. 实施前确认实际迁移序号，添加成对 up/down。新增黄金表、索引、账户子类校验及交易关联列，保留全部原账户标识、期初、余额、基金、券和负债历史。不自动创建个人黄金持仓，不写测试示例为真实资产。
2. 在隔离 MySQL 库运行旧结构升级与回滚条件验证，验证十进制精度、唯一关联、并发幂等与封账；不得迁移真实开发财务库来跑测试。上线执行前按仓库规则备份并检查部署实际版本。
3. 前后端同批发布支持 `gold` 和未知余额的契约，部署顺序确保新资源不会由旧 UI 错算；启动小时调度及可恢复重建，必要时仅对测试账号创建临时黄金账户验收。
4. down 在任何黄金账户、个人持仓/事件/审计/幂等引用或黄金资金关联存在时明确拒绝，不能清空财务数据后自动回滚。仅公共报价且无个人资源时可移除公共表与空关联列；先停止 worker 再执行。存在财务数据的应用回退须保留能识别黄金资产的兼容版本或前滚修复，禁止直接启动只认现金/基金的旧版。
5. 验收产出桌面及 360px 截图、查询故障/恢复记录、核算示例和迁移说明。真实建行 smoke 仅显式开启后读取公开报价，不创建个人持仓、不进行真实交易。
