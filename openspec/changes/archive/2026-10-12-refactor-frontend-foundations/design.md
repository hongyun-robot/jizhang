## Goals / Non-Goals

**Goals:**

- 每类状态只有一个明确管理模块，调用方使用简短且能约束合法操作的 Interface。
- 用可观察结果验证会话、金额、缓存、草稿和导航行为；页面抽取不改变现有财务口径。
- 逐个业务迁移，任何阶段可通过类型检查、定向验收和独立提交回滚。

**Non-Goals:**

- 不把服务器资金分配、账期、幂等或权限裁决搬到前端；前端预测仅为展示。
- 不建立通用 CRUD 页面引擎，不以文件行数强行拆分，不引入新的全局表单状态库。
- 不在本次工作中统一改写全站“今天”的时区；券继续使用北京时间，其余入口保留现有日期语义并在工具接口明确输入。
- 不全面迁移旧 SQL 验收的测试后端；本变更新增写入验收必须使用独立 fixture，旧脚本按其文档单独运行。

## Decisions

### 1. 数据模块按业务拆分，跨业务失效规则集中

在 `api/` 下建立 `transactions.ts`、`accounts.ts`、`categories.ts`、`statistics.ts`、`vouchers.ts`、`recurring.ts`、`budgets.ts`、`notifications.ts`、`settings.ts` 和 `users.ts`，负债的 DTO 与请求分别组织。`hooks.ts` 可暂时重导出，所有调用方迁移后移除；避免让旧文件永久成为第二套实现。

统一 JSON 请求解包并保留二进制导出的独立入口，错误区分未授权、无权限、业务拒绝、网络失败和表单校验。查询向 Axios 传递 `AbortSignal`；不吞掉取消错误、不将写操作默认设为自动重试。读写的响应类型明确，移除成功载荷上的无依据断言。

由 `queryKeys` 生成包含会话代次和标准化参数的 key。例如普通列表、无限列表及费用候选共享交易根键，后缀区分数据形状；无限查询 key 必须包含 page_size 与起始页，不能仅用 URL 页码代表已追加缓存。`invalidateFinancialViews` 在一个地方描述资金写入影响，涵盖两种流水、余额、统计、预算、负债、券、提醒及封账预览。账户/分类资料更新使用较窄的映射；新平台名称保存需要同步目录。

写入已提交成功与后续重取失败分开呈现，不能把后续网络失败报告成“资金保存失败”并诱导重复提交。选择性等待当前活跃视图更新，后台更新状态可追踪；未观察的失效缓存按正常挂载策略重取。

备选是只把长文件按行移动，或各写入 Hook 继续列一组失效字符串。两者仍会遗漏新查询形态，因此采用业务根键与统一影响映射。

### 2. 会话协调模块管理刷新与退出时序

`stores/auth.ts` 保留身份状态，提取共享身份类型（会话用户和管理列表用户字段明确区分）；会话模块提供恢复、登录、退出和受拒 token 刷新四类操作。原始认证请求不经过自动刷新拦截器，传输依赖可注入以测试并发时序，避免请求层、store 和页面相互调用清理。

401 处理比较“被拒 token”与当前 token：若已有新 token 则直接重试，否则进入当前代次的单飞刷新；每个原请求仅重试一次。刷新设置合理超时，保留请求体和 request_key，403 直接上报。终止认证失败统一结束会话；瞬时网络失败保留明确重试状态，不把无法读取当成合法匿名数据。

登录、退出和换号递增会话代次，旧读取、刷新、补处理和 mutation 的客户端回填必须核对代次。退出先停止新刷新及后台任务，处理在途刷新与 cookie 轮换后注销当前服务器会话，再清理本地业务缓存、导航记忆和草稿；网络失败仍结束本地会话并忽略旧响应。主题不作为业务会话状态清理。请求取消作为优化，代次校验才是迟到响应保护依据。

备选是收到 401 就清空 token，或仅调用 QueryClient.clear；前者无法处理刷新成功后迟到的旧 401，后者无法阻止刷新回填，因此采用明确的会话生命周期。

### 3. 导航与权限独立于布局

把 `lastSearch`、返回目标与路径匹配放入导航模块，`AppShell` 和 Dashboard 不再通过导入布局文件使用导航工具。返回目标用统一站内地址类型，序列化 pathname、search、hash，做同源、basename 和访问资格检查，支持 `/` 与 `/jizhang/`。Tab 筛选记忆挂在当前会话，显式 URL 是恢复筛选的首要来源。

`domain/permissions.ts` 提供资金创建、普通流水修改、周期模板管理、个人负债资料管理等具名判断。资源保护（券事件、分期管理、封账拒绝）与角色资格分开组合；保留服务端返回的 `can_edit_purchase` 等具体能力。已可验证的只读新建入口先修正，其他入口逐页接入同一判断。导航配置与路由访问要求共用最小元数据，不构建包含所有页面内容的路由/菜单超级配置。

备选是全面使用单一 canRecord 判定所有操作；它会错误禁止只读成员设置本人账户和创建平台选项，因此按资源语义组织。

### 4. 查询状态和编辑草稿具有明确时序

完善 `QueryState` 的实际错误、初次加载、成功空态与后台更新失败呈现，组件不接受 `isError` 布尔值来替代错误对象。首页多区块和统计各图表按各自查询展示失败，已知数据可读；预算、审计、账户、分类、周期、提醒、用户管理、设置和负债均接入错误与重试。提醒已读失败显示错误而不伪造全部已读。通知及负债历史的 JSON 解析用类型守卫，兼容未知类型，避免坏记录导致整页异常。

草稿与服务器快照分开：以对象 ID 或账期作为编辑 key，记录 dirty；首次打开初始化一次，选项迟到只填尚未编辑的空值。后台数据可以更新快照或提示，但不覆盖草稿。保存成功只重置相同编辑 key 的草稿；预算切换 dirty 账期时确认放弃，取消则保持原账期。保持各业务当前控件，不为少量表单创建通用 schema 表单引擎。

备选是关闭全部后台重取，或 effect 每次用远端对象重填；前者会让余额/提醒失去及时更新，后者会丢输入，因此分离远端快照和草稿。

### 5. 金额、分类与日期提供可测试的纯模块

- 统一 `lib/money.ts` 的精确解析、求和、比较、绝对值、格式化和末份补差；非法金额返回明确校验结果，不能静默成为合法零元。金额上下限沿用后端契约。首页资金汇总和最终金额文本使用整数分；图表坐标和动画中间值才转换为 Number，动画终点使用精确文本。券次数不受分期 120 期上限误约束，券操作成本直接复用服务器固定份额数据，不展开全部次数。
- 分类模块一次构造按 ID 索引、所属一级、完整标签和可选叶子；复用 CategoryPicker 并保留退款可留空、禁用和键盘行为。账户选项模块区分新消费、历史回显、资产付款与个人负债，不简单把所有停用账户从历史表单中丢弃。
- 抽取可传参考日期的预设区间和真实日历校验。PeriodPicker 从受控 value 回显端点，只保留确有必要的面板草稿；`lib/liability.ts` 的账单预览保留服务器规则版本、短月份和生效日期语义，使用已有后端场景样例对照验证，不新增另一套资金计算。
- 单一流水筛选模型生成 URL、接口条件、摘要与导出条件；导出只移除 page/page_size，关联退款保留关联 ID 并按现有规则不加日期限制。非法 URL 回落不产生无意义查询或历史条目；关键词请求加入短防抖，显式地址与历史恢复仍即时生效。

备选是引入新的金额库、继续复制树遍历或让所有日期入口依赖一个隐式全局时区。现有整数分已经够用，统一小接口和显式日期输入能减少更多维护点。

### 6. 页面按流程和状态复杂度拆分

建议布局：

```text
src/
  api/                   传输、查询键、各业务查询与 typed 请求
  auth/                  会话协调
  domain/                权限、身份与分类/账户展示模型
  navigation/            会话导航记忆、返回目标
  hooks/                 确实共享的视口与弹层行为
  lib/                   金额、日期和账单展示预测
  features/
    records/             筛选模型、列表状态、筛选控件、行操作
    vouchers/            列表、详情、事件操作及表单
    liabilities/         汇总/详情、账单/计划展示、各操作表单
    recurring/           周期模板表单与列表
    statistics/          图表配置和文本数据表
  components/            跨业务基础展示与控件
  pages/                 路由入口，组合相应 feature
  styles/                基础、主题、布局及组件覆盖
```

先搬移有稳定 Interface 的内容，再拆流程，迁移期间短期重导出可降低同时改动量。Records 将 URL/分页/追加缓存交给列表 Hook，触摸刷新、自动续载与定位交给页面内部 Hooks；行展示模型和操作策略共用，桌面与移动 DOM 仍分别渲染。保留 POP 与追加 REPLACE 的区别、分页回顶、locateId 一次性清理、IntersectionObserver 和 touchcancel 清理。

券页面分列表/详情/操作弹窗，保留当前同一 request_key 在超时后复用；用户修改后重试收到 409 并提示核对的既有 `voucher_retry.mjs` 行为不改。平台选项的迟到创建响应保护保留，只整理 Interface 和名称。

负债 Dialog 使用以 mode 判别的联合类型，只有对应模式才要求 billId、planId、txnId、version 等字段。数据模块封装七类端点与具体输入；表单不再自行拼 URL 和 unknown。创建/调整分期与结清各有独立草稿，版本及 request_key 在同次重试中稳定，结清预览与当前提交字段绑定，修改关键字段后必须重新核对。汇总与详情拆成独立路由入口，避免列表路由和详情路由同时取不必要数据；将重复 find/filter 的跨记录映射集中成展示模型。

统计页的四类图表配置为纯构造函数，EChart 只管理实例、主题、尺寸和释放，替换无约束的 AnyOpt；显示数据表继续基于同一聚合结果。备选是把整页封进一个更大的 Hook；那会让调用方学会大量状态与 setter，故按实际流程分模块。

### 7. 布局不承担补处理，弹层共享视口状态

`useBackgroundReconciliation` 管理周期、券和负债的现有启动/60 秒触发策略，按现有服务器权限处理各任务，不把自动补齐等同于手工资金权限。每个任务防在途重叠、退出时停止，新会话独立启动；客户端协作不替代服务端幂等。无新增且无失败变化的券检查不失效全部资金视图；由于“generated 为 0”不一定表示提醒等状态没有更新，负债检查仍可有针对性刷新负债/提醒。

把 visualViewport 监听收敛为应用级单一观察源或有引用计数的激活模块，移除一个弹层不会清理仍被其他弹层需要的根变量。逐个接入券、个人负债、负债操作、普通记账等弹窗，公共 modal behavior 只封装避让、内容滚动和 popup container，不强迫业务使用同一布局。确认提交在异步验证开始时即防重；失败保留字段。备选是每张表单复制监听与 Modal 样式，无法稳定维护多弹层生命周期。

### 8. 加载优化与样式重组分别交付

按路由 lazy import，首屏共享壳和认证链保持精简；Mine 的用户管理面板按实际展开加载。提供 Suspense 加载反馈和资源加载失败恢复，刷新恢复保持原 URL。ECharts 通过 core 注册当前实际需要的 Pie/Line/Bar、Tooltip、Legend、Grid 与 CanvasRenderer 及代码中使用的其他能力，移除未使用的 `echarts-for-react`，不盲目拆出所有依赖。

基线相同环境下，目标是首页首次加载的所有静态 JS 及 modulepreload 合计 gzip 降至基线 70% 以下（约 602 kB），且 ECharts 不在登录/首页的首次静态依赖图中。同时记录首次打开统计页与总构建大小，不能只通过改变 chunk 文件名宣称优化成功。

CSS 先按当前顺序无行为拆分，再逐个合并页面局部规则与媒体查询；保持 768px 内容断点和 992px 导航断点的不同语义。共用主题值供 CSS、AntD 与图表消费；首屏内联主题脚本继续在渲染前工作。优先使用 AntD token/组件配置，剩余覆盖保留范围清晰的选择器，不一次性删除所有 important。备选是重做设计或换样式框架，超出本次范围且放大验收面。

### 9. 补小型单元测试，复用既有浏览器验收

增加 `test:unit`，采用 Vitest 4.1.0 或同系列兼容补丁作为开发依赖，以独立配置测试纯模型、传输和会话时序。规划期通过 `npm view vitest@4.1.0 engines dependencies.vite --json` 核实其支持 Node 20/22/24 和 Vite 6/7/8；不直接安装要求 Node 22.12+ 的最新版，避免改变仓库 Node 20+ 契约。官方使用方式参考 [Vitest 指南](https://vitest.dev/guide/)，具体兼容范围以所选版本的包元数据和安装锁文件为准。

浏览器组件与交互继续用 Playwright，提取 fixture 探测、登录、API、浏览器路径、等待、截图和清理辅助，保留现有独立脚本入口。新增回归使用本地隔离服务与独立资源标识，读写前检查 fixture，清理放在 finally；不为样式搬移写镜像实现的测试，不用大面积快照替代资金断言。

## Risks / Trade-offs

- [会话重试与已提交资金操作混淆] → 认证重试保留载荷和操作键，提交后重取失败单独报告，保留已提交超时/409 回归。
- [缓存键整体迁移遗漏调用方] → 普通/无限/候选根键统一，财务影响表测试覆盖全部写入入口，旧重导出只临时保留。
- [权限抽取误套个人负债例外] → 按四角色、本人/他人、资产/负债、普通/受管理流水构造表驱动用例；API 仍最终裁决。
- [日期预测与服务器规则偏离] → 使用服务器现有短月份、生效版本和费用归期场景作为前端 fixture；无法匹配时以服务器结果展示，不重新定义账务。
- [草稿保护使服务器变化不易察觉] → 后台更新保留字段并显示更新提示，明确保存/切换/取消时的生命周期。
- [页面迁移破坏触摸、定位、主题和可及性] → 各阶段定向浏览器验收，360/767/768/991/992/1280px 及明暗、减弱动效截图复核。
- [资源拆包后旧缓存请求不存在的 chunk] → 提供加载失败恢复入口，回滚部署保留上一版资源的可用窗口；不改变站内 URL。
- [测试工具升级隐含提高 Node 要求] → 锁定已核实的兼容测试版本，新增依赖仅开发使用，独立类型检查测试配置。

## Migration Plan

1. **阶段一：测试与状态修复。** 建立单元/隔离浏览器辅助，迁移请求解包与查询键，修复会话、导航、权限、错误态和草稿覆盖。以并发 401、退出迟到响应、当前流水页购券刷新、关联退款导出及只读入口为验收重点。
2. **阶段二：公共业务模块。** 统一金额、分类、账户选项、区间和筛选参数，迁移 typed 负债请求、身份类型及通知解析。通过纯逻辑、金额尾差、日期边界和重试契约测试。
3. **阶段三：页面拆分。** 逐个迁移 Records、周期、券、负债和统计页面，整理补处理与弹层生命周期。逐页运行相关验收，保持旧入口可用，消除过渡重导出。
4. **阶段四：加载与样式。** 先路由/图表拆包并测量，再保持顺序拆 CSS 和集中主题值；运行跨页面资金回归、断点与视觉验收，产出前后体积、桌面/移动截图及跳过检查说明。

每阶段按一个目的组织提交；错误修复、页面迁移和纯样式整理不混在同一提交。完成全部任务后才进行实现验证与 OpenSpec 归档。发布属于后续明确部署任务；无数据库迁移，回滚使用上一前端构建或对应提交，保留既有 API、cookie、URL 与财务数据。回滚不撤销已经发生的真实资金操作。
