# 直接新建理财零钱

2026-10-16 用户补充：关联入口用于兼容历史账户，新建账户必须能直接输入起始余额并选择理财产品。

## 行为与实现

“账户管理 → 新建账户”选择资产类别“理财零钱”，输入非负起始余额、选择产品和起算基准日，保存后直接成为可支付且已启用的理财零钱。基准日默认今天，允许改为已核对的历史日期，从下一日起随实际披露净值记收益。记账的账户选择器内联创建也支持同一表单，完成后自动选择新账户，支出默认快转。原有现金账户继续从关联入口启用，既有数据不改写。

沿用 `POST /accounts`，新增可选 `wealth_cash` 对象，只有新建 `asset_class=wealth_cash` 时提交产品/日期资料。账户、配置、创建审计及账户请求回执在既有 `LedgerWrite` 内原子提交。与历史关联共用准确产品身份、开放状态、日期和策略默认校验；创建不依赖实时银行网络。不要求前端先创建普通账户后发第二个关联请求。

请求摘要包含起始余额与理财资料，同内容重试返回原账户，改变余额、产品或日期复用标识会冲突。可选字段为空时省略，固定旧版普通账户摘要回归通过。新建检查数据库中的本人状态和记账权限；只读用户不可启用自动收益。缺失/非法配置、负余额、金额精度错误、未开放产品、非法日期、审计及回执存储失败全部回滚，不遗留账户或消耗请求标识。

本次复用已上线的 000021 表结构，不增加迁移。

## 验收

- Go 定向测试覆盖直接创建、owner 防伪、自动收益、当前余额重试、跨接口请求键冲突、余额/产品/日期变更冲突、角色权限、未开放产品、非法参数、审计/回执失败全回滚及旧版普通账户摘要兼容。
- MySQL 理财零钱 3 项顶层测试通过，新增并发 8 次创建只得一个账户/配置/审计/回执，并以真实 SQL trigger 验证审计失败整笔回滚后同请求可重试。既有迁移、封账、手改与资金回滚回归保持。
- `go test ./...`、`go vet ./...`、`go build ./cmd/server`、前端类型检查与构建通过；前端 29 文件 / 90 测试通过。
- 桌面与 360px 手机各 14 项断言通过，覆盖产品必填、起始余额、日期、回执丢失草稿保留、相同请求标识重试、一次请求直接配置、自动收益、创建审计展示和支付入口内联创建。历史关联兼容流程回归 15 项通过。

通过临时 member 账本执行 14 项生产验收：一次 `POST /accounts` 直接创建起始余额 10000 元、已关联民生 E 的理财零钱，相同请求重试返回同一账户。真实源成功获取 754 条净值，取 2026-10-14 的 1.068000 为基准、10 月 15 日 1.068033 为最近净值，现有后台任务自动入账 0.31 元，余额为 10000.31 元；重复刷新无重复流水、资产无重复计入。
