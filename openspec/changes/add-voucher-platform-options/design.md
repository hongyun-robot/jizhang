## Context

动机见 `proposal.md`。当前实现中，`VoucherFormModal.tsx` 共用于登记和编辑券，`platform` 是普通 `Input`；`VoucherInput`、API 请求和 `vouchers.platform` 均使用可选文本。`VoucherInput.normalize()` 已执行 `strings.TrimSpace` 和 128 字符校验，购买与编辑在 `repository.LedgerWrite` 事务中完成。

项目为单账本共享模式，没有租户或家庭 ID。生产数据库通过 SQL migrations 升级，测试使用 SQLite AutoMigrate，另有隔离 MySQL 迁移 / 并发测试和桌面 / 手机浏览器验收。路由已有 `VoucherSvc` 依赖及 `voucherHandler`，可复用其组装方式。

`add-vouchers` 已完成但未归档，平台 / 商家文本兼容和券权限以其当前实现及 delta 为背景；本变更只新增独立目录能力。主规格 `identity/access-control` 的只读写限制需明确非账务选项创建例外，见本变更对应 delta。

## Goals / Non-Goals

**Goals:**

- 将选项持久化与券的字符串值分离，保留现有客户端及历史数据兼容性。
- 使用同一名称校验与创建逻辑处理输入框内创建、券保存补入及并发重试。
- 将选项接口接入现有登录认证，并避免借用券写权限或管理员设置权限。
- 限定改动在券模块和现有表单，复用依赖、错误包装与测试设施。

**Non-Goals:**

- 不将券改为外键引用选项，不引入平台 / 商家多级模型、租户模型或别名合并。
- 不扩大券表单入口和任何财务事件的权限，不引入选项管理后台。

## Decisions

### 1. 单独保存共享名称目录，券继续保存字符串

新增 `VoucherPlatform` 模型与 `voucher_platforms` 表，仅包含 `id`、`name VARCHAR(128)` 和 `created_at`。名称建立唯一索引，生产名称列明确使用 `utf8mb4_bin`，与 SQLite 的精确字符串唯一性保持一致。所有选项共享，名称不可在本次功能中改名或删除，无需用户归属或软删除字段。

`vouchers.platform` 保持字符串：字段值是选项名称，而非 ID。选项 ID 仅用于目录记录身份及重复创建响应，不进入券请求。

替代方案：只读取券中的 DISTINCT 名称不增加表，但无法保留明确创建后尚未保存券的选项，且删除最后一张券会使选项消失；浏览器本地存储无法跨成员与设备共享；选项外键会改动旧接口和历史数据，收益不足。

### 2. 明确名称校验和去重边界

抽出供目录服务和券保存使用的名称规范化逻辑：去首尾空白、按 Unicode 字符计数、保留内部文字。选项创建要求规范化后 1–128 字符；券字段仍允许空字符串，空值跳过目录写入。长度校验针对规范化后的值，处理器不得用原始长度校验提前拒绝本应合法的名称。

本次假定“相同名称”为规范化后文本完全一致：`美团` 与 `  美团  ` 相同，`JD` 与 `jd`、不同标点、不同内部空白视为不同。搜索可忽略英文字母大小写，但搜索匹配不改变目录的名称身份。此规则避免数据库默认不区分大小写或重音的 collation 静默合并用户名称。

仓储提供基于数据库唯一约束的 create-or-get：尝试插入，名称冲突时读取同名记录并返回，其他错误正常上抛。不能采用无唯一约束的“先查再插”，也不能吞掉非唯一冲突错误。事务内调用时仓储绑定传入的 `tx`，不打开新的数据库连接或独立事务。重复创建统一返回成功，故无需为选项创建额外设计请求 UUID。

### 3. 在登录路由中增加目录 API

复用 `VoucherSvc` 和 `voucherHandler`，新增独立资源路由，避开 `/vouchers/:id`：

| API | 输入 | 成功响应 data | 行为 |
| --- | --- | --- | --- |
| `GET /api/v1/voucher-platforms` | 无 | `[{ id, name }]` | 全量读取，按名称精确排序、ID 兜底，空时返回 `[]` |
| `POST /api/v1/voucher-platforms` | `{ "name": "美团" }` | `{ id, name }` | 创建或返回同名项，HTTP 200 |

使用现有 `{code, message, data}` 响应格式；无效名称返回 400，未登录按现有认证返回 401，存储错误返回 500 并提供清晰提示。严格解析 JSON，限制沿用项目请求体策略。

两个接口只挂 `middleware.Auth`，不挂 `RequireRoles`，服务也不调用 `CanCreateTransaction`。选项创建不依赖账期、账户、券所有权或统计缓存失效回调。现有券路由 writer 组、服务内归属校验和前端入口显隐保留，因此只读成员能调用目录 API，但不会新增购券入口。

替代方案：挂在券 writers 组会违反“没有权限要求”；复用分类管理接口会错误引入管理员限制与消费分类语义。

### 4. 显式创建独立提交，随券补入同事务提交

下拉框“创建「名称」”调用目录 POST，成功即可持久化，即使之后取消购券也保留；键入或失焦不触发目录 POST。

若用户仅输入新名称后提交，`VoucherService.Create` / `Update` 在既有 `LedgerWrite` 事务内、权限与业务校验通过后 ensure 非空名称。券、购买记录、目录新增和相关账务一起提交，任一失败则一起回滚。已有明确创建的目录项不会因后续券保存失败而被删除。

保持现有购券 request key 和 payload hash 的处理顺序，尤其不得在校验失败或请求 key 冲突路径上提前写入目录。成功的幂等重试可在同事务内 ensure 已有券的名称，不重建购买事件或改变扣款行为。更新旧券无需选项 ID；删除券不删除目录。平台 / 商家只是元数据，不改变成本分摊、账期及资金流水投影逻辑。

替代方案：前端先建目录再提交每笔券，会让无意确认的失败购券留下选项，也无法覆盖旧客户端；保存后单独写目录会出现券保存成功而目录遗漏。

### 5. 用可输入的下拉组件统一登记与编辑体验

在现有 `Form.Item name="platform"` 中使用 Ant Design `AutoComplete` 配合 `Input`，保留输入框形态、可见展开入口、清空、占位提示及长度约束。点击输入框或展开入口显示目录；按输入内容做前端包含搜索，目录规模按家庭账本使用量采用一次全量读取。

输入值与候选选项分离，字段始终保存用户输入或选中名称。没有完全同名项且输入合法时，候选列表提供“创建「名称」”，用标记区分创建动作和普通名称，不将“创建”文案或虚拟值写入表单。空目录显示“输入平台 / 商家名称可创建”；可匹配其他候选且无完全同名项时仍允许创建当前输入。

支持点击和键盘确认创建，避免按 Enter 处理候选时冒泡触发 `form.submit()`。创建请求期间显示状态、禁用该动作的重复触发；券提交等待当前明确创建动作结束或防止并行重复提交。创建失败保留草稿、显示错误并允许重试或直接保存券，不把目录创建失败当作券已保存。

异步响应按表单打开轮次和发起时输入值判断是否仍应选中；用户已修改字段、清空、关闭或切换编辑对象后，仅更新目录缓存，不回填旧值。加载目录不得自动选首项或覆盖历史值，取消表单恢复现有 reset 逻辑。

新增独立 `['voucher-platforms']` 查询与创建 mutation；只有表单打开时加载，重新打开时可刷新。显式创建后立即合入缓存并刷新目录；成功购券 / 编辑后使目录查询失效。目录 mutation 只更新自身缓存，不调用财务写后的全量失效路径。读取失败在字段附近提示并提供重试，仍保留手动输入和随券保存能力。

替代方案：普通 Select 的搜索值与选中值分离，需额外处理未选中时的原始输入；多选 tags 会改变字段语义；原生 datalist 难以表达明确创建动作、请求状态和现有样式。

### 6. 历史回填和验证沿用现有设施

新迁移 `000006_voucher_platforms.up.sql` 创建表，并从 `vouchers` 的 `deleted_at IS NULL`、非空 `platform` 精确去重回填。现有券服务已规范化持久化名称，回填不修改 `vouchers`；不加入硬编码平台种子。down 仅删除目录表，不修改券和账务。

SQLite 相关服务、处理器和浏览器测试 fixture 均需加入新模型的 AutoMigrate；MySQL fixture 在创建 / 更新券前应用 000006，并另设历史回填、唯一约束与并发创建验收。浏览器 fixture 增加普通成员供无管理员权限创建验收，沿用现有隔离测试账本及脚本。

## Risks / Trade-offs

- [目录和券字符串可能不同步] → 所有成功券创建 / 更新均在同事务内 ensure 名称，迁移补入既有值；保留字符串接口和旧客户端回归用例。
- [SQLite 与 MySQL 去重语义不同] → 明确精确名称规则与生产列 collation，用隔离 MySQL 验证中文、大小写、空白去重及并发 create-or-get。
- [延迟响应污染编辑表单] → 创建响应校验输入值与表单轮次，目录加载不参与字段初始化，浏览器覆盖切换 / 关闭与重试。
- [目录持续增长且没有管理入口] → 当前家庭账本采用全量目录和本地过滤；改名、删除、别名与分页需求留到独立变更。
- [回退会丢失独立创建且未用于券的选项] → 应用回退时优先保留附加表；确需执行 down，先导出目录以备恢复。

## Migration Plan

1. 以当前已实现的 `000005_vouchers` 和券代码为基础，新增 000006；实施时若迁移编号已被占用，使用下一个空闲编号并同步测试引用。
2. 在隔离 MySQL 中验证历史回填、大小写精确去重、并发创建、随券写入回滚，以及 down 不改动券和账务。
3. 先应用数据库新增迁移，再发布支持目录接口和随券补入的后端，最后发布下拉表单前端。旧前端继续使用原字符串接口。
4. 应用需要回退时可回退至本变更之前、仍支持券功能的前后端，保留目录表。执行数据库 down 前导出独立目录选项；恢复时重新应用迁移并导入备份。不得据此回退到不识别券账务用途的旧版本。
